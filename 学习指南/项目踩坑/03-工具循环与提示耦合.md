# 03 · 工具循环与提示耦合

模块：`schema.go`、`agent.go`（工具循环）、`resultstore.go`、`main.go`（工具注册与 prompt）。
一句话：**模型的行为由「prompt + schema + 文案」三者共同决定，而它们分散在三个地方**——这正是最容易漏改的地方。

---

### K-10 截断必须留痕

`agent.go:271-287`：截断时既写 `res.Context.Warnings`，同时打 stderr。

- **原理**：静默截断 = 数据损坏。模型会拿残句当完整事实继续推理，人也以为拿到的是全文。
- **面试**：截断为什么要让模型也知道？【实现层追问】

### K-11 文案必须与能力对齐（踩过，很值得讲）

`agent.go:277-286` 的注释记录了一次真实事故：旧文案写着「原始内容不可恢复，需完整内容请走外置 + 召回」——那是代码在向模型承诺一个**当时还不存在**的能力，模型照着要却什么也拿不到，只能幻觉。

- **修法**：文案随能力走。现在 `resultstore.go:391-394` 的标记要同时给三件事：这是什么、怎么读回来、**读回来的确切调用**（`read_result(handle=..., offset=1, limit=200)`）。少了最后一项，模型经常回一句「内容被截断了」就停了。
- **面试**：为什么模型会出现「内容不可用」这种回答？【实现层追问】——答案：不是模型笨，是提示词在骗它。

### K-12 方法值注册顺序：nil 接收者 panic

`main.go:96-98`：`read_result` 是 `resultStore.ReadResult` 的**方法值**，所以 `tools` 必须在 `ResultStore` 建好之后才能建。顺序反了不报编译错，而是注册进一个 nil 接收者，模型一调就 panic。

- **面试**：为什么这个工具要放在仓库之后注册？【实现层追问】

### K-13 工具名必须显式覆盖成 snake_case

`main.go:99-104`：反射/方法值推出来的名字是 `ReadResult`（首字母大写）。工具名是给模型看的，生态惯例是 `snake_case`（Anthropic 官方示例一致）。忘了覆盖，模型看到的就是个不合惯例的工具名。

- 补充：`newTool(getColor, ...)` 这类普通函数推出来是 `getColor`，也不合惯例——只是当前恰好能跑。
- **面试**：工具名有规范吗？不规范会怎样？【加分拓展】

### K-14 system prompt ↔ tool schema 隐性耦合（本项目最容易漏的一处）

`main.go:46-60`：**加工具必须同步改 prompt**。模型只从 system prompt 和 tools schema 知道自己有什么能力——只加 tools 不改 prompt，模型不会主动去用。

`read_result` 那段 prompt 还要写清三件事：
1. **触发条件**：看到「已外置…句柄 res-3」这种标记时；
2. **调用方式**：`read_result(handle, offset, limit)` 按行翻页；
3. **禁止行为**：不要说「内容不可用」，也不要猜被砍掉的部分。

少了第 3 条，模型很可能只回一句「内容被截断了」就停下。

- **面试**：加一个工具需要改几处？【实现层追问】——这是「隐性耦合」的典型，也是可讲的架构债：schema 与 prompt 应该同源生成，而不是两处手写。

### K-15 每个 tool_use 都必须有一条 tool_result

`agent.go:250-264`：三条路径都要回。

- 工具不存在（模型幻觉/名字写错）→ 回 `is_error` 的 result；
- 执行失败 → 回 `is_error` 的 result；
- 成功 → 回正常 result。

少一条，这个 tool_use 就悬空，下一轮请求要么被 API 拒，要么模型自己编一个结果继续。

- **面试**：工具调用失败时应该怎么处理？【高频变形原题】

### K-16 外置的「诚实边界」

`resultstore.go:356-389` 三层行为，每层都有明确语义：

1. **没超配额**：原样返回（绝大多数调用走这条，零 IO）。
2. **超配额**：全文落盘，上下文只留头部 + 省略提示 + 尾部 + 句柄。
3. **落盘失败**：退回 L0 纯截断，**并且在标记里写明「完整内容已丢失」**——绝不假装无损。

另外 `store == nil` 也走 L0，这让功能可以分步落地（先接闸门、再建仓库），也让 `agent.go` 不用写 `if m.results != nil`。

- **面试**：外置一定能保证无损吗？【实现层追问】——它依赖磁盘可写，这是必须说清的边界。

### K-17 缓存断点必须用构造函数，不能用零值

`context_assembler.go:263-279`：

- `anthropic.TextBlockParam{}` 零值构造出来 `Type == ""`，发出去要么被 API 判非法断点，要么**断点静默失效**。必须用 `anthropic.NewCacheControlEphemeralParam()`。
- 默认关的两个现实理由：① 官方要求前缀达到最小长度（1024/2048 token）才真写入缓存，本项目 system 远不够；② 记忆块每轮变化，杀伤半径不止自己——它之后整个 messages 的缓存都陪葬。
- `TestAssembleStablePrefixFirst` 钉住了这一点。

- **面试**：prompt cache 的断点打在哪？为什么会失效？【加分拓展】
