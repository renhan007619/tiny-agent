标准三路快排写法有两种：

写法 A（Dutch national flag，j 为已处理区的右开边界）：
```
i=lo, m=lo, j=hi+1  // 或者 j=hi
while m<j:
   if a[m]<p: swap(i,m); i++; m++
   elif a[m]==p: m++
   else: j--; swap(m,j)
```
这里 j 初始为 hi+1，最后区间是 [lo,i-1] <, [i,j-1] ==, [j,hi] >。

用户写的 j=hi，循环 m<j，然后 else 里 swap(nums[j],nums[m]); j--。当 j=hi 时，nums[hi] 是还没处理的元素（初始时 nums[lo..hi] 中，lo 是 pivot，m=lo+1，j=hi，nums[hi] 还没处理，是有效的待处理元素）。所以循环条件 m<j 意味着只处理 m 到 j-1，漏掉了 nums[j]（即 nums[hi]）本身！

### 🤖 助手

##### 一句话结论

这里只有一个 bug，位置在 `partition` 的循环条件：`for m < j` 少了等号，应该是 `for m <= j`。

问题在于 `j` 在 else 分支里用作“待处理区最右端（含）”，但循环条件却按“右端（不含）”来写。这两种定义混在一起，导致 `nums[j]` 可能一次都没有被比较过，却被调用方当成“等于 pivot 区”永久跳过。这个 bug 不会 panic，也不会死循环，只会结果错，而且随机化让它时好时坏。

---

##### 为什么 `j` 的语义矛盾

【逐行理解】对照 else 分支：

```go
}else{
    nums[j],nums[m]=nums[m],nums[j]
    j--          // 这里：把“最右端的待处理元素”换到 m 处，右边界左移一格
}
```

`j--` 的写法说明 `j` 是“最后一个还没分类的下标”，也就是闭区间右端。既然 `j` 本身也是待处理位置，循环就必须处理 `m == j` 那一格，所以条件是 `m <= j`。

用 `m < j` 的后果：

- 扫描中若从未触发过 else（一路 `<` 或 `==`），则 `m` 会一路增长到等于 `j`，此时循环直接退出，`nums[j]` 从头到尾没被读过；
- 而 `partition` 返回 `(i, j)`，调用方的语义是 `[i, j]` 为等于区，`quick` 只递归 `[lo, i-1]` 和 `[j+1, hi]`；
- 于是，这个没被检查过的 `nums[j]` 被当作“等于 pivot”排除在递归之外，再也不会参与比较，最终永久错位。

触发条件很具体：本次扫描没有出现 `> pivotval` 的元素，并且 `nums[hi] < pivotval`。

---

##### 手推一个会错的例子

`nums = [2,1,1]`，第一层随机到 `pivot = lo`（即选中 index 0，概率 1/3）：

```
pivotval = 2, i=0, m=1, j=2
nums[1]=1 < 2  → swap(0,1) → [1,2,1], i=1, m=2
m < j ? 2 < 2 假 → 退出
返回 (i,j) = (1,2)
```

返回后 `[1,2]` 被当成等于区（其实 `nums[2]=1` 是小于区），只递归 `quick(0,0)` 和 `quick(3,2)`，两者都不做事。

结果 `[1,2,1]`，没排好。而 `nums[2]` 那个 `1` 自始至终一次都没被比较过。

##### 修法（二选一，别混着用）

【必记】**方案 A（最小改动）**：保留 `j = hi` 和 `j--` 的闭区间语义，只把循环条件补上等号：

```go
for m <= j {     // 唯一改动
```

此时结束时 `m == j+1`，`[i, j]` 恰好是等于区，`return i, j` 和 `quick(lo,i-1)/quick(j+1,hi)` 全部保持不变。`nums[lo]` 那个 pivot 副本会一直待在 `i` 位，被 swap 反复“挤”到 `[i, m-1]` 里，所以 `[i, j]` 确实是纯等于区，边界自洽。

【必记】**方案 B**：若坚持 `m < j`，那 `j` 必须改成“大于区左边界”的开区间语义，三处一起改：

```go
i, m, j := lo, lo+1, hi+1   // j 初值 +1
...
}else{
    j--                      // 先减
    nums[j], nums[m] = nums[m], nums[j]
}
...
return i, j - 1              // 返回值也要跟着变
```

现在你的代码是“方案 A 的初值和返回值 + 方案 B 的循环条件和 else 顺序”，取了两边的错位组合。

---

##### 顺带建议

【理解】**随机化反而成了这个 bug 的掩护**。`pivot` 随机，同一份输入可能这次对下次错，跑几百个用例还能通过。排这类区间边界 bug，最有效的方法是固定几个小数组手工推一遍（`[2,1,1]`、`[2,3,4]`、`[1,1,1]`、`[2,1]`），而不是加大数据量。

【略读】修好后复杂度不变：期望时间 `O(n log n)`（n 为数组长度），最坏 `O(n²)`（pivot 每次取到极值，随机化后概率极低）；空间期望 `O(log n)` 递归栈，最坏 `O(n)`。三路分区在“大量重复元素”输入下是 `O(n)`，这是它在 912 上比普通二分快排稳的原因。

【略读·加分】可以把“先递归较小的那一半”加上去，把最坏栈深压到 `O(log n)`：

```go
if i-lo < hi-j { quick(lo,i-1); quick(j+1,hi) } else { quick(j+1,hi); quick(lo,i-1) }
```

面试里问“三路快排为什么能抗重复元素”和“边界怎么定”时，标准答法是**三要素必须自洽：j 的初值 = j 在 swap 中的用法 = 返回值给调用方的区间语义**。你这段就是典型反例，面试官很喜欢拿这种“少个等号”的写法考人。

用户问：为什么在三路快排中最后的标杆不用和 i 位置互换？

用户在对比普通二分快排（Hoare/Lomuto）：普通快排最后要把 pivot 换到正确位置（比如 Lomuto 最后 swap(nums[i], nums[lo])），而三路快排的代码里最后没有 swap 回 lo。

答案核心：因为初始时已经把 pivot 换到 nums[lo]，然后 m 从 lo+1 开始扫描，i 从 lo 开始。关键洞察：pivot 元素本身（nums[lo]）在扫描过程的第一层"<"分支中，会被交换到后面，但它始终落在 [i, m-1] 这个"等于区"里？不，其实更准确：

pivotval 这个值被拿出来当标杆，但 nums[lo] 位置上那个具体元素，其实一直在参与分区——它最终会落在 [i, j] 的等于区里，因为它的值就等于 pivotval，而分区规则保证了 [i, m-1]（或 [i,j]）内的元素值全部等于 pivotval。

##### 二路 Lomuto 为什么必须换

二路快排里 `i` 是“小于区右开边界”，代表一个**待填的空位**：`lo` 位置被 pivot 占着，但语义上 `lo` 应该属于小于区，于是整个扫描过程中 `lo` 一直是个临时的存放位置。循环结束后：

- `[lo, i-1]` 全 `< p`
- `[i, hi]` 全 `≥ p`
- pivot 仍然在 `lo` 位置

此时 `swap(nums[lo], nums[i])` 一次操作完成两件事：把 pivot 送到分界点 `i`，把 `i` 那个 `≥ p` 的元素挪到 `lo` 填补空位。**pivot 的最终位置只能靠这次交换来确定**，不换就无法定位。

##### 三路为什么不用换，以及换了为什么会错

三路里 `i` 不再是空位，它是**等于区的左端点**。三个不变量如下：

```
[lo, i-1] < p      [i, m-1] == p      [j+1, hi] > p
```

关键在初始状态：`i = lo, m = lo+1`，此时 `[i, m-1] = [lo, lo]`，长度是 1，**这唯一一个元素就是 `nums[lo]`，它的值正是 pivotval**。等于区在循环开始前就已经存在了，并非尚未建立。

再看 `m - i` 这个长度怎么变化：

| 分支 | 动作 | `m - i` |
|---|---|---|
| `<` | `i++` 且 `m++` | 不变 |
| `==` | `m++` | **+1**（等于区扩张）|
| `>` | `j--`，i/m 不动 | 不变 |

初始 `m - i = 1 > 0`，而之后只增不减，所以 **`m - i ≥ 1` 恒成立**，也就是“等于区永远非空、`nums[i]` 的值永远是 pivotval”。这一行就是整个问题的答案。

于是对于 `<` 分支，它做的是把 `i` 位置上那个“等于值”换到 `m`、然后双指针同步右移，等于值被向右移动，`i` 处换成新来的小值。**pivot 元素被一路向右移动，但始终留在 `[i, m-1]` 这间“等于区”里。** 循环结束时 `[i, j]` 整段都等于 pivotval，pivot 元素就在其中，它的位置并不需要单独确定。

现在看如果强行补上 `swap(nums[lo], nums[i])`：

- 若 `i == lo`（一个 `<` 元素都没有）：自交换，无害但也没用。
- 若 `i > lo`：由不变量，`nums[lo]` 此刻是一个 **小于 pivotval** 的值，`nums[i]` 是一个**等于 pivotval** 的值。这一交换等于把一个小值塞进等于区、把一个等于值扔进小于区，使得 `[lo, i-1] < p` 和 `[i, j] == p` 同时失效。调用方拿到返回值 `(i, j)` 后会把那个小值当“已归位的等于值”跳过，**最终结果直接出错**。

所以这并非“多余步骤”，它的效果是在正确结果上**注入一个错误**。二路和三路在这一步上有本质区别。

##### 一个类比

二路快排像“给一个人安排座位”：pivot 是唯一主角，你必须亲自把他领到座位上，所以有收尾那个 swap。

##### 改完为什么仍然正确

Lomuto 的循环不变式是：`[lo, i-1]` 存放**已比较过且满足条件**的元素，`i` 是它们的下一个空位，`[i, j-1]` 存放不满足条件的元素。

循环结束后执行 `swap(nums[i], nums[hi])`：

| 写法 | 循环后状态 | 交换后 |
|---|---|---|
| `<` | `[lo,i-1]` 严格小，`[i,hi-1]` 大于等于 | `[lo,i-1]` 小，`[i]`=pivot，`[i+1,hi]` 大于等于 |
| `<=` | `[lo,i-1]` 小于等于，`[i,hi-1]` 严格大 | `[lo,i]` 小于等于，`[i+1,hi]` 严格大 |

两边的“小于等于区 / 大于区”都成立了，`i` 处也确实换成了 pivotval，返回 i 后递归 `[lo,i-1]`、`[i+1,hi]` 都合法，**不会死循环，也不会越界**。所以你说“行不行”，答案是行。

##### 它到底改变了什么

只改变了一件事：**值等于 pivotval 的元素去了哪一边**。

- 用 `<`：划分成 `小 | 大等于`，等值元素全落进**右侧**递归区间；
- 用 `<=`：划分成 `小等于 | 大`，等值元素全落进**左侧**递归区间。

两边都只是把等值元素从一边挪到另一边，**没有任何一方把它们“拎出来”并从递归中剔除**。这正是关键：三路快排之所以能抗重复元素，是因为 `partition` 返回 `(i, j)` 一段区间，等于区**不进入递归**；而 Lomuto 无论怎么写，都只返回一个下标，等于 pivot 的元素永远得继续参与后面的分区。

所以面对全相等的数组 `[1,1,1,...,1]`：

- `<`：`i` 一步不动，返回 lo，右区间规摸 n-1，递归 n 次 → `O(n²)`；
- `<=`：`i` 冲到 hi，返回 hi，左区间规模 n-1，递归 n 次 → 同样 `O(n²)`。

**两者一样退化。** 想真正解决，只能换三路（或双路 Hoare 变体），改条件符号这种手段并不解决根本问题。

##### 真正需要注意的两个问题

【必记】**问题一：`i` 位置必须存放“已经比较过”的元素。** Lomuto 的正确性完全依赖这一点。因此 pivot 必须放在 **hi**，并且循环只能扫描 `lo..hi-1`；你贴的 `j < hi` 正好符合。如果 pivot 是换到 `lo` 的，那 `j := lo; j < hi` 就会把 `nums[hi]` 完全漏掉，**和你上一轮三路快排那个“少个等号”是同一类 bug**（边界元素没被比较，被当成已归位永久跳过）。回头务必确认你的 pivot 落在 hi 还是 lo。

【理解】**问题二：`<=` 会让 `j == i` 时出现无意义的自交换**（`swap(nums[i], nums[i])`），不影响结果，但说明代码没有区分“值小于 pivot”和“值等于 pivot”这两件事。Lomuto 本来就不区分，用哪个符号都行，但别把这种模糊当成优化。

##### 结论

如果 pivot 取最左侧元素 `nums[lo]`，那么分区收尾时要执行 `swap(nums[lo], nums[i])`。这一步要求**相遇点 i 上的值 ≤ pivot**。先移动 j 正好能保证这一点；如果先移动 i，相遇点可能是大于 pivot 的值，这个值会被换到 lo，进而导致整个分区错误。

更根本地说：**规则是“先移动与 pivot 相对的那一侧”**，并非永远“先动 j”。pivot 在左侧就应先动右指针，pivot 在右侧则要先动左指针。

---

##### 为什么先动 j 就能保证

先看两个内层循环的停止条件（假设 pivot 在 lo）：

```go
for i < j && nums[j] >= pivot { j-- }   // j 停下时：nums[j] < pivot
for i < j && nums[i] <= pivot { i++ }   // i 停下时：nums[i] > pivot
```

关键在错误写法中容易被忽略的一点：**两个守卫都是 `i < j`，所以 i 和 j 相邻时，“先动的那一方”会直接移动到对方的位置并停下。**

那么，双方相遇后，这个位置上的值是谁留下的？

- 如果 **j 先移动**，它最终会移动到 i 的位置；此时 i 位置的值是**上一轮交换后由 j 放进去的小值**，或者是初始的 `nums[lo]`，也就是 pivot 本身。因此相遇点 ≤ pivot，`swap(lo,i)` 安全。
- 如果 **i 先移动**，它最终会移动到 j 的位置；此时 j 位置的值是**上一轮交换后由 i 放进去的大值**，或者初始的 `nums[hi]`。因此相遇点可能 > pivot，`swap(lo,i)` 会把大值放到最左，分区就失效了。

用一句话概括：**j 停下时带来“小于 pivot”的属性，i 停下时带来“大于 pivot”的属性；收尾交换需要的是前者，所以要让 j 成为最后移动的那一个。**

---

##### 反例手推一下（`nums = [2,1,3]`，pivot = 2）

**先动 j（正确）：**

```
j: nums[2]=3 >= 2 → j=1；nums[1]=1 < 2 → 停
i: nums[0]=2 <= 2 → i=1；i==j 停
相遇 i=j=1，nums[1]=1 < 2 ✔
swap(0,1) → [1,2,3]，递归两侧都空 → 正确
```

**先动 i（错误）：**

```
i: nums[0]=2 <= 2 → i=1；nums[1]=1 <= 2 → i=2；i==j 停（j 一步没动）
相遇 i=j=2，nums[2]=3 > 2 ✘
swap(0,2) → [3,1,2]，返回 2
左区间 [0,1] 再排成 [1,3]
最终 [1,3,2] —— 错的
```

这里错误的原因是：i 一路向右移动，把 j 挤在末尾没有机会移动，最终停在完全没验证过相对大小的 `nums[hi]=3` 上。

注意，这种错误并不会每次出现。比如 `[5,3,4]` 用先动 i 的写法恰好也能排对（因为 pivot 是最大值，落点正好在最右）。这和上一轮“随机化掩盖 bug”一样：顺序写反了，错误只会在**特定大小关系**下暴露，测试不容易抓到。

##### 镜像规则

| pivot 位置 | 先动谁 | 收尾交换 | 需要相遇点满足 |
|---|---|---|---|
| `nums[lo]` | 先动 j（右） | `swap(lo, i)` | `nums[i] ≤ pivot` |
| `nums[hi]` | **先动 i（左）** | `swap(i, hi)` | `nums[i] ≥ pivot` |

判断方法就是看收尾要满足什么不等式，再找一个停止条件能提供该不等式的那一侧指针，让它最后移动。

顺带说明：**Hoare 1961 年的原始版本没有这个讲究**。它取中间元素作 pivot、用 do-while 且不带 `i<j` 守卫、返回的是 j 而不是 i，递归区间是 `(lo, j)` 和 `(j+1, hi)`。面试里常说的“为什么先走右边”特指“pivot 取最左 + 收尾 swap(lo,i)”这种民间变体。

---

##### 注意事项与面试考点

【必记】**守卫必须是 `>=` / `<=`，不能写成 `>` / `<`。** 全等数组时，如果把内层条件写成 `nums[j] > pivot { j-- }`，i、j 都不会移动，外层 `i<j` 永远成立且没有交换，会**直接死循环**。带等号至少能保证指针必然前进。

【高频变形原题】“手写快排时为什么先移动右指针”是极高频追问，标准答案就是“收尾交换要求相遇点 ≤ pivot，而 j 的停止条件恰好提供这个性质”。

【实现层追问】该写法的两个退化场景要能说出来：① 有序数组 + 固定取 lo 作 pivot → `O(n²)`（每次返回 lo，只削掉一个元素）；② 全等数组（即使有 `>=` 守卫）→ j 一路移动到 i，返回 lo，同样 `O(n²)`。随机化只解决前者，重复元素必须通过三路分区解决。

【加分拓展】挖坑法（把 pivot 存进临时变量、先移动右指针填补 lo 的空位）之所以也是“先动右”，原因相同：空位在左，就要从右取料。把“先动哪侧”归结到“空位、落点在哪侧”这一层，比背诵“先动 j”更不容易记反。

复杂度照旧：分区 `O(n)`；整体期望 `O(n log n)`、最坏 `O(n²)`（n 为数组长度）；空间是递归栈，期望 `O(log n)`、最坏 `O(n)`。

##### 结论

方向对，但要改两个词：

1. **“碰巧”应改成“必然”** —— pivot 恰好是该次分区区间的最大值时，先动 i 不会出错，这是可证明的；
2. **“最大数”要限定为“该次 partition 调用区间的最大值”，不是整个数组的最大值** —— 所以哪怕某一层侥幸满足，递归到子区间时不满足照样错。

反过来：**只要该区间存在大于 pivot 的元素，先动 i 就一定出错。**

---

##### 为什么“最大值时对”是必然

先动 i 的循环结束时，`i == j == x`，x 位置的值只有两个来源：

- **被交换写过** → 写进去的必然是从 i 那边换来的**大于 pivot** 的值；
- **从没被交换过** → 就是原始 `nums[hi]`。而 i 能一路走到 hi，说明 `lo+1..hi-1` 全都 ≤ pivot；再加上 `nums[lo]=pivot` 本身 ≤，合起来就是**整个区间 ≤ pivot**，即 pivot 是最大值。

所以：

- pivot 不是最大值 → 必然落进第一种来源 → `nums[x] > pivot` → `swap(lo,x)` 把大值填到最左边，而最左边属于“≤ pivot 区”，分区被污染；
- pivot 是最大值 → 全区间都 ≤ pivot → 相遇点是什么都安全 → 交换不会破坏性质。

这不是概率问题，是结构决定的：**交换机制让 j 位置永远存大值、i 位置永远存小值**；先动 i 时最后一步踩到的是 j 位置（大值），先动 j 时踩到的是 i 位置（小值）。

---

##### 一个最小的反例：`[1,2]`

只有两个元素，`pivot = nums[0] = 1`：

```
先动 i：i 内层 nums[0]=1 <= 1 ✔ → i=1，i==j 停
        j 内层守卫不成立，不动
        swap(nums[0], nums[1]) → [2,1]，返回 1
        结果 [2,1] —— 直接错
```

两个元素就崩，这个例子比 `[2,1,3]` 更能说明问题的严重性。而且 pivot=1 是**最小值**，正是最坏情形。

---

##### “最大值时对”不等于能用

即使某层满足，递归下去照样可能炸。`nums = [3,2,1]`：

```
第一层 pivot=3（最大值 ✔）
  i 一路走到 2，相遇点 nums[2]=1 ≤ 3 ✔
  swap(0,2) → [1,2,3]，返回 2

左区间 [0,1] = [1,2]，此时 pivot=1（最小值 ✘）
  i 走到 1，swap(0,1) → [2,1]
最终 [2,1,3] —— 错
```

要全程正确，得**每次** partition 的 lo 都是该子区间的最大值，实际输入里基本不可能（全等数组除外，全等时 pivot 既是最大也是最小，但对任何一侧都不占便宜，仍然 `O(n²)`）。

所以实用结论：随机选 pivot 之后，某次分区恰好落在最大值的概率约 `1/区间长度`，样本一大，先动 i 几乎必然暴露错误。别指望碰运气。

##### 面试考点

【必记】**把“正确性”和“效率”分开谈**。先动 j 对任意输入都正确（相遇点由 `nums[j] < pivot` 背书），但它仍有退化：有序数组固定取 lo 作 pivot 会 `O(n²)`；全等数组也会 `O(n²)`。正确性问题是“顺序写反”，效率问题是“pivot 选得差”，别混为一谈。

【高频变形原题】“为什么先动右、如果先动左会怎样” —— 标准答法：收尾 `swap(lo,i)` 要求 `nums[i] ≤ pivot`，j 的停止条件恰好提供这个性质。

【实现层追问】边界上要能举出 `[1,2]` 这种两元素反例，比空谈“可能出错”有力得多。

【加分拓展】能把“相遇点在最大值情形下为何安全”讲成“全区间 ≤ pivot，落点取什么值都不破坏划分”，说明你理解的是不变量而不是死记规则。

复杂度不变：单次分区 `O(n)`；整体期望 `O(n log n)`、最坏 `O(n²)`（n 为数组长度）；空间是递归栈，期望 `O(log n)`、最坏 `O(n)`。

用户贴了三段代码，问：三路是 `m<=j`（有等号），二路 Hoare 是 `i<j`（无等号），一路 Lomuto 是 `j<hi`（无等号），怎么解释这个等号的有无？

这是个很好的统一性问题。需要找到统一原则解释为什么三路要等号，另两个不要。

先看三段代码：

**三路（闭区间版）：**
```go
i,m,j := lo,lo+1,hi
for m<=j {
    if nums[m]<pivotval { swap(i,m); i++; m++ }
    else if nums[m]==pivotval { m++ }
    else { swap(j,m); j-- }
}
return i,j
```
这里 j 是"待处理区右端（含）"，m 是当前扫描位。循环条件是 m<=j，因为 j 位置本身也是待处理元素，m 可能正好停在 j 上（当所有元素结束时 m 追上 j，j 位置最后一个元素还需要处理）。

**二路 Hoare：**
```go
i,j := lo,hi
for i<j {
    for i<j && nums[j]>=pivotval { j-- }
    for i<j && nums[i]<=pivotval { i++ }
    swap(i,j)
}
swap(lo,i)
```
这里 i 和 j 是"相向而行的两个扫描指针"，各自负责从两端找"该换的"。i<j 表示"还有两个不同的位置"，一旦 i==j 说明所有元素都已经就位，相遇点就是 pivot 的最终位置，不能再处理（此时 i 位置已经是分界点，不是待处理元素）。

**Lomuto（一路）：**
```go
i:=lo
for j:=lo;j<hi;j++ {
    if nums[j]<pivotval { swap(i,j); i++ }
}
swap(i,hi)
```
j 从 lo 到 hi-1，hi 是 pivot 本身不参与，所以 j<hi。

统一解释的角度：

1. **边界语义不同**：三路里 j 是"含在待处理范围内"的下标（闭区间），所以 m 要能走到 j；二路里 i<j 是"两个指针不能重叠"的条件，重叠即终止；Lomuto 里 hi 不是待处理元素（它是 pivot），所以 j<hi 排除它。

2. 更统一的原则：**循环条件取决于"右端那个位置是不是待处理元素"**。
   - 三路：`j` 指向的元素**还没被分类**（它是待处理区的最后一个元素），所以 `m == j` 时还要处理一次 → `m <= j`。
   - Lomuto：`hi` 指向的元素**就是 pivot 本身**，被临时拿出来了，不属于待处理 → `j < hi`。
   - Hoare：`i` 和 `j` 是相向扫描的，`i == j` 时说明整个区间已被两侧消化完，相遇点是"已确定"的，不是待处理 → `i < j`。

3. 另一个角度：**"区间是开的还是闭的"**。
   - 三路：待处理区间 `[m, j]` 是闭区间，j 位置的元素待处理，循环继续条件 `m <= j`。
   - Lomuto：待处理区间 `[lo, hi)` 是左闭右开，hi 是 pivot，条件 `j < hi`。
   - Hoare：扫描在 `(i, j)` 之间进行…… 更准确：`[i, j]` 两端都是"指针"而不是"待处理区"，`i<j` 保证不相撞。

4. 还有一层：**等号对应"最后一个元素要不要处理"**。
   - 三路：有元素还没处理完（j 位置的元素），要等号。
   - Lomuto：pivot 不参与循环，不要等号。
   - Hoare：i 和 j 相遇时，相遇点由 j 的停止条件保证已经满足性质，不需要再处理，不要等号。

我觉得最清晰的统一解释是：**看循环结束时，右端那个下标上的元素有没有被处理过**。

- Lomuto `j<hi`：hi 位置是 pivot，被 swap 到临时变量语义上"取出"（实际值是变量 pivotval 保存的），不参与循环。
- Hoare `i<j`：i 和 j 不是"待处理区边界"，是"两个还在搜索的指针"；i==j 时，相遇点确认（由 j 侧停止条件保证安全），不需要再动。

##### 结论

**循环条件本身不看“几路”，而只看“右端点是不是待处理元素”**，等号并非规则：

- 待处理区间**含**右端点 → 写 `<=`
- 待处理区间**不含**右端点 → 写 `<`

三路是闭区间，所以有等号；Lomuto 和 Hoare 的右端点不是待处理元素，所以没有。

---

##### 三者的 `j` 根本不是同一个东西

| | 右端点代表什么 | 待处理区间 | 循环条件 |
|---|---|---|---|
| **三路** | 还没分类的**最后一个元素** | `[m, j]` 闭 | `m <= j` |
| **Lomuto** | `hi` 是 pivot 本体，已被 `pivotval` 取走 | `[lo, hi)` 左闭右开 | `j < hi` |
| **Hoare** | `i`、`j` 是对向搜索指针，`i==j` 就是相遇点 | `(i, j)` 开 | `i < j` |

- 三路的 `j` **指向一个真实待处理元素**：`m` 走到 `j` 时，那个元素还没被判断过，必须再处理一次 → 等号。
- Lomuto 的 `hi` **指向 pivot 自己**：它的值已经在 `pivotval` 变量里，位置上这个元素由收尾 `swap(i,hi)` 负责，不在循环职责内 → 不等号。
- Hoare 的 `i`、`j` **指向两个还在搜索的指针**：`i` 左边已经全 ≤ pivot、`j` 右边已经全 ≥ pivot，`i==j` 时区间已消化完，相遇点就是 pivot 的落点，没有待处理元素 → 不等号。

一句话：**循环条件就是“待处理集合非空”的翻译**。集合闭 → 带等号；集合开 → 不带。

##### 为什么只有三路写错就真的错

这是三段代码最实质的差别：**三路的边界是唯一防线，另外两个都有冗余守卫兜底。**

- **Lomuto**：条件 `nums[j] < pivotval` 天然把 pivot 自己排除（pivot 不小于自己）。就算你把范围误写成 `j <= hi`，`nums[hi] < pivotval` 也是假，不会触发交换，结果照样对。是“不敏感”，不是“应该写”。
- **Hoare**：两个内层循环都带 `i<j` 守卫，指针相撞后不会再动。外层就算误写 `i <= j`，也只是多一次 `swap(i,i)` 自交换，无害。
- **三路**：没有任何第二道守卫。`j` 位置不处理就**永远不处理**，而且 `return i, j` 会把它当作“等于区”交给调用方跳过 —— 正是你第一轮那个 `m<j` 的 bug：静默错排，不 panic、不死循环、随机化下时好时坏。

【必记】**三种分区里，只有三路的边界写错不会被别的条件救回来。** 这就是它最容易翻车的原因，也是为什么“等号”这个点只对三路构成真实考点。

---

##### 关键的一点：等号可以消掉

“三路必须写等号”是**闭区间写法的副产品**，不是本质。换一套配套写法，等号就没了：

```go
i, m, j := lo, lo+1, hi+1   // j 当“大于区左边界”用
for m < j {                  // 没有等号
    ...
    }else{
        j--                  // 先减
        nums[j], nums[m] = nums[m], nums[j]
    }
}
return i, j-1                // 返回值随之改成 j-1
```

这时 `j` 语义变成开边界，循环条件自然就是 `<`，而且没有等号。

所以真正的规则只有一条：**initial value、循环条件、分支里的自增自减、返回值，四处必须描述同一个区间**。你第一轮的 bug 就是“闭区间的初值和返回值”配了“半开区间的条件”。

【必记】回答“为什么三路有等号”时，不要说“三路就是要有等号”，要说“三路的 `j` 是待处理区最后一个下标，属于待处理元素”。这体现你按语义判断而非背模板。

【实现层追问】能当场把闭区间版和第上面开区间版互相转换，并说清每处改动，是很好的加分项。

##### 最短的例子：`[2,1]`（只有两个数）

错误版循环是 `for m < j`。

```
quick(0, 1)：  i=0  m=1  j=1
m < j ？  1 < 1  → 假，一次都不进循环
```

整个分区**什么都没干**，直接 `return 0, 1`。

这个返回值的含义是：从下标 0 到 1 的数都已经归位。于是 `quick(0,-1)` 和 `quick(2,1)` 都是空区间，整个函数结束。

如果随机选到 pivot 是下标 0，数组原样就是 `[2,1]`，输出 `[2,1]`，两个数都没排。

（选到下标 1 时，开头那次 `swap` 恰好把 `[2,1]` 换成 `[1,2]`，所以这例子有一半概率蒙对。这正是它难查的原因。）

---

##### 换成 `[3,2,1]`，看清“漏掉的是谁”

假设随机选中下标 0，`pivotval = 3`：

```
开始     [3, 2, 1]
         i=0  m=1  j=2     pivotval=3

m<j？1<2 ✔
nums[1]=2 < 3  → 换 i 和 m
         [2, 3, 1]
         i=1  m=2  j=2

m<j？2<2 ✘ 停

return 1, 2
```

关键看 `nums[2]=1` 这个数：

**眼睛（m）刚走到它头上，循环就退出了，它一次都没进过 if。** 你不知道它是小、是等、还是大，因为你根本没看它。

而 `return 1, 2` 向外面宣布：“下标 1 到 2 都等于 pivot(3)”。可 `nums[2]` 是 1，压根不是 3。

调用方信了这句话：`quick(0,0)` 空、`quick(3,2)` 空。**那个 1 被永久当成“已经摆好”跳过了。**

结果 `[2,3,1]`，错。

---

##### 不是运气问题

`[3,2,1]` 三种 pivot 选择全错：

| 随机选中 | 输出 |
|---|---|
| 下标 0 | `[2,3,1]` |
| 下标 1 | `[2,1,3]` |
| 下标 2 | `[1,3,2]` |

三种都不对。所以别指望“多跑几次就正常了”。

---

##### 加上等号，同一组数据就对了

`[3,2,1]`，还是假设选中下标 0：

```
开始     [3, 2, 1]
         i=0  m=1  j=2     pivotval=3

m<=j？1<=2 ✔
nums[1]=2 < 3  → 换 i 和 m，i=1, m=2
         [2, 3, 1]

m<=j？2<=2 ✔   ← 就差这一次
nums[2]=1 < 3  → 换 i=1 和 m=2，i=2, m=3
         [2, 1, 3]

m<=j？3<=2 ✘ 停

return 2, 2
```

这次 `nums[2]=1` 被看了一眼，发现它小于 3，于是被换到了左边。返回 `(2,2)` 只声明“下标 2 是 pivot 3”，符合事实。

再递归排左边 `[2,1]`，得到 `[1,2,3]`，正确。

核心复杂度：

**单次 partition**：都是 O(n) 时间，O(1) 额外空间（原地）。

**整体排序**：
- 时间：期望 O(n log n)，最坏 O(n²)
- 空间：递归栈，期望 O(log n)，最坏 O(n)

但三种在"最坏情况触发条件"和"重复元素表现"上有差异，这才是重点。

**一路 Lomuto**：
- 时间：期望 O(n log n)，最坏 O(n²)
  - 最坏触发：已排序/逆序 + 固定取端点 pivot；或者大量重复元素
  - 关键问题：**等于 pivot 的元素全部进入一侧递归**，所以重复元素多时退化。全相等数组：每次分区只排除 pivot 一个元素，T(n) = T(n-1) + O(n) = O(n²)。
- 空间：递归栈，最好/期望 O(log n)，最坏 O(n)（退化成链）
- 特点：实现最简单，但分区常数因子大（交换次数多），且对重复元素最差。

**二路 Hoare**：
- 时间：期望 O(n log n)，最坏 O(n²)
- 空间：同上
- 特点：交换次数少（平均约 n/6 vs Lomuto 的 n/2？需要小心数字）。Hoare 的分区交换次数平均是 n/2? 让我想想：Lomuto 每次满足条件的元素都要交换（包括 i==j 自交换很少），Hoare 每轮内层扫完才交换一次。经典结论：Hoare 的分区扫描次数更少（约 3n/2 比较？）。
  
  实际上经典数据：Lomuto 平均交换次数比 Hoare 多约 3 倍。Hoare 的 partition 平均约 n/6 次交换，Lomuto 约 n/2 次？我记不准，不要给具体数字，只说"Hoare 交换次数更少"。
  
- Hoare 对重复元素的处理：遇到等于 pivot 的元素会停止扫描并交换（因为条件 >=，等于时停？不对，条件 `while nums[j] >= pivot j--`，等于时 j 继续走；`while nums[i] <= pivot i++`，等于时 i 继续走）。

  注意：Hoare 版本有很多变体。经典 Hoare 条件是 `while a[i] < pivot i++` 和 `while a[j] > pivot j--`（等于时停），这样等于元素被均匀分到两边，重复元素多时能保持平衡。但用户写的是 `<=` 和 `>=`（等于时不停），这样等于元素会全堆到一边，退化。

- 特点：重复元素多时最优，一次分区把等于区整段排除。

##### 一张表看全

以下 n = 数组长度，均假设 pivot 随机化（你的代码就是）。

| | 一路 Lomuto | 二路 Hoare | 三路（Dutch flag） |
|---|---|---|---|
| 单趟分区时间 | O(n) | O(n) | O(n) |
| 单趟额外空间 | O(1) | O(1) | O(1) |
| 平均时间 | O(n log n) | O(n log n) | O(n log n) |
| 最坏时间 | O(n²) | O(n²) | O(n²)（几乎碰不到） |
| 递归栈平均 | O(log n) | O(log n) | O(log n) |
| 递归栈最坏 | O(n) | O(n) | O(n) |
| **全相等数组** | **O(n²)** | **O(n²)** | **O(n)** ✅ |
| 分区返回 | 1 个下标 | 1 个下标 | 2 个下标 |

**核心事实：三种的快排单趟都是 O(n) + O(1)，所以整体差异全部来自“这一趟把区间切得多均匀”。**

---

##### 逐个说为什么

【理解】**一路 Lomuto**

每趟只做一件事：把所有 `< pivot` 的元素拨到左端，然后 `swap(i,hi)` 只把 **pivot 这一个元素**放到位。

所以每趟最多排除 1 个元素。遇到已排序数组（pivot 又恰好取端点）或者大量重复值，就是：

```
T(n) = T(n-1) + O(n)  →  O(n²)
```

全相等的数组最惨：`nums[j] < pivotval` 永远为假，一次都不交换，`i` 纹丝不动，收尾交换等于自交换，只排除一个元素 → O(n²)。

---

【理解】**二路 Hoare**

两个人从两头往中间扫，扫到“该换”的就换一次。交换次数比 Lomuto 少很多，但**同样只返回 1 个下标**，相当于每趟也只确定一个分界点。

关键在于你这份写法的停止条件：

```go
for i<j && nums[j] >= pivotval { j-- }   // 等于 pivot 时不停，继续走
for i<j && nums[i] <= pivotval { i++ }   // 等于 pivot 时不停，继续走
```

**元素等于 pivot 时不会停下来**，于是它们全被赶到同一侧，本质和 Lomuto 一样“不区分等于”。全相等数组时 `j` 一路走到 `lo`、`i` 不动，返回 `lo`，又是只排除一个元素 → O(n²)。

（经典 Hoare 的另一种变体让等于时也停，能把重复元素均分到两侧、保持平衡。但那是另一套写法，不是你现在这份。）

---

【理解】**三路**

一趟扫描把区间切成 **三块**：小于区、等于区、大于区。返回 `(i, j)`，等于区 `[i, j]` **整段不进入递归**。

所以对重复元素有“批量删除”的效果：

- 全相等数组：所有元素都走 `nums[m]==pivotval` 分支，`m` 一路扫到底，返回 `(lo, hi)`，等于区就是整个数组，两边都是空区间 → **一趟结束，O(n)**。
- 大量重复但还有大小混杂：每趟至少把等于 pivot 的那一批一次性排除，剩下的规模快速缩小。

它的最坏 O(n²) 理论上仍存在（每次 pivot 都恰好是极值、且没有重复值），但随机化之后触发概率可以忽略。

---

##### 空间那栏是怎么来的

三种都是**原地排序**，除了递归栈没有额外空间。

栈深 = 递归树的深度：

- pivot 随机 → 期望切得比较均匀 → 树高 O(log n) → 栈 O(log n)
- 最坏（每次只排除 1 个元素）→ 退化成一条链 → 栈 O(n)

【加分】**三种都能把最坏栈深压到 O(log n)**，用的技巧一样：先递归短的那一侧，长的用循环继续（尾递归改写）。

```go
// 思路示意：短的先递归，长的留下继续循环
if i-lo < hi-j { quick(lo, i-1); lo = j+1 } else { quick(j+1, hi); hi = i-1 }
```

因为短的先处理完就出栈了，栈里同时存在的层数不会超过 O(log n)。

---

##### 三个必记点

【必记】**平均都是 O(n log n)，最坏都是 O(n²)，差别在“最坏多容易出现”和“重复元素怎么处理”。** 面试问复杂度不要只答 O(n log n)，要主动补最坏情形。

【必记】**重复元素是分水岭**：一路和二路（等于不停那版）遇到全相等退化 O(n²)，三路反而 O(n)，这正是三路存在的意义。LeetCode 912 用三路更稳，原因就在这里。

【必记】**递归栈要单独说**，不能和第二点混成一句“空间 O(1)”。原地排序说的是不额外开数组，栈是另外算的。

---

##### 面试考点

【高频变形原题】“快排最坏什么时候 O(n²)，怎么避免” → 答三件事：pivot 取端点 + 有序输入；随机化把最坏变成期望；三路解决重复元素。

【实现层追问】“Lomuto 和 Hoare 哪个快、为什么” → Hoare 交换次数更少（每轮扫完才换一次，Lomuto 是每见一个小的就换），但 Hoare 边界更容易写错、返回值的语义也更绕。

【加分拓展】能主动说出“栈深可以靠先递归短边压到 O(log n)”，以及“三路返回两个下标就是为了让等于区不递归”，这两句足以拉开与只会背模板的差距。
