### 🤖 助手

##### 一句话本质

这题是**回溯（DFS）模板题**：枚举每个格子作为起点，四向深搜逐字符匹配，走过的格子当场标记、递归返回时撤销。所有花活都在剪枝上。

---

##### 一、最优解法：回溯 + 三层剪枝

骨架就三步，闭着眼都能写：

1. **枚举起点**：双重 `for` 扫全图，每个格子都试着当 `word[0]`。
2. **四向深搜**：`dfs(i, j, k)` 表示「正匹配 `word[k]`，站在 `(i,j)`」。入口先判越界、再判 `board[i][j] != word[k]`，不等立刻 return。
3. **标记 + 撤销**：进入前把 `board[i][j]` 改成 `'#'`（保证同格不复用），四个方向试完再改回去。

###### 三层剪枝（进阶部分的核心）

| 剪枝 | 做法 | 效果 |
|---|---|---|
| ① 频次剪枝 | 统计 board 字符频次，若 word 里某个字符要得比 board 有的多，直接 false | O(mn)，能秒杀一票构造用例 |
| ② 反转起点 | 若 `word` 末尾字符在 board 里比首字符更稀有，把 word 反转 | 起点候选数从「首字符出现次数」降到「更稀有那端」，等价合法因为路径可逆 |
| ③ 自然剪枝 | 父格被标记成 `'#'`，回到它时字符必不等，自动剪掉 | 每层分支从 4 降到 **3**，这是复杂度里 `3^L` 的来源 |

###### Go 代码

```go
func exist(board [][]byte, word string) bool {
	m, n := len(board), len(board[0])
	L := len(word)

	// 统计 board 字符频次（剪枝 ① 和 ② 共用）
	var cnt [128]int
	for i := 0; i < m; i++ {
		for j := 0; j < n; j++ {
			cnt[board[i][j]]++
		}
	}
	// 剪枝 ①：word 需要的字符数不能超过 board 供给
	need := cnt // 值拷贝，别把 cnt 本身消耗掉
	for i := 0; i < L; i++ {
		if need[word[i]] == 0 {
			return false
		}
		need[word[i]]--
	}
	// 剪枝 ②：从更稀有的那端开始搜
	if cnt[word[L-1]] < cnt[word[0]] {
		b := []byte(word)
		for i, j := 0, L-1; i < j; i, j = i+1, j-1 {
			b[i], b[j] = b[j], b[i]
		}
		word = string(b)
	}

	dx := [4]int{0, 0, 1, -1}
	dy := [4]int{1, -1, 0, 0}

	var dfs func(i, j, k int) bool
	dfs = func(i, j, k int) bool {
		if i < 0 || i >= m || j < 0 || j >= n || board[i][j] != word[k] {
			return false // 越界 / 字符不匹配 / 撞到已标记的 '#' 都在这一行拦掉
		}
		if k == L-1 {
			return true // 最后一个字符也匹配上了
		}
		board[i][j] = '#' // 标记已使用
		for d := 0; d < 4; d++ {
			if dfs(i+dx[d], j+dy[d], k+1) {
				board[i][j] = word[k] // 提前 return 也要恢复，统一在这里做最稳
				return true
			}
		}
		board[i][j] = word[k] // 撤销
		return false
	}

	for i := 0; i < m; i++ {
		for j := 0; j < n; j++ {
			if dfs(i, j, 0) {
				return true
			}
		}
	}
	return false
}
```

两个细节值得注意：
- **恢复用 `word[k]` 而不是临时变量**：入口已经确认 `board[i][j] == word[k]`，原值就是它，省一个变量、也省一次栈上分配。
- **别用 `defer` 恢复**：每层递归都挂一个闭包，L=15 时开销明显，手动恢复更快（面试官看到 `defer` 可能追问性能）。

---

##### 二、复杂度

设 `m`、`n` 为网格行数列数，`L = len(word)`。

- **时间**：`O(m·n·3^L)`。外层 `m·n` 个起点，每层最多展开 3 个新方向（父格被标记，第 4 个方向必失败），深度 `L`。剪枝只会让它更快，不改变上界。裸搜不标记是 `4^L` 量级。
- **空间**：`O(L)`，只有递归栈；不计输入。若改用 `visited [][]bool` 则是 `O(m·n)`。

---

##### 三、对比解法

| 方案 | 时间 | 空间 | 取舍 |
|---|---|---|---|
| **回溯 + 原地标记**（最优） | `O(mn·3^L)` | `O(L)` | 省掉 visited 矩阵，但改了输入 |
| 回溯 + visited 数组 | 同上 | `O(mn)` | 面试官要求「不许改 board」时用这个，`m,n≤6` 时空间可忽略 |
| 每个起点跑一遍 BFS | 指数级且状态爆炸 | `O(mn)` | **不能用**，同一个格子可以从不同路径到达，BFS 的「 visited 判重」在这里是错的（见下方易错点） |
| 单词搜索 II（LC 212）的朴素版 | `O(k·mn·3^L)` | `O(kL)` | 多个词就每个词跑一遍本题；正解要上 Trie |

###### 【高频变形原题】
- **LC 212 单词搜索 II**：从「一个词」变「一堆词」。正解是把 word 列表建成 Trie，DFS 沿 Trie 指针走，走到终止节点就收集。为什么不能每个词跑一遍：`k` 个词整体是指数级叠加，Trie 把公共前缀的搜索**合并**了一次，复杂度降到 `O(mn·3^L)`（L 为最长词长）。这题几乎是 79 的必考后续。
- **LC 130 被围绕的区域 / LC 200 岛屿数量 / LC 1219 黄金矿工**：同一套「网格 DFS + 访问标记」骨架。关键区别是——**岛屿类的标记不需要撤销**（求连通块，一次遍历到底），**路径类的标记必须撤销**（不同路径会复用同一格）。能一句话讲清这个区别就够本了。

###### 【实现层追问】
- **为什么是 `3^L` 不是 `4^L`？** 父格被标成 `'#'`，回溯到它时字符必然不等，在入口那行就 return 了。
- **提前 `return true` 时要不要恢复 board？** 本题已经全局返回了，不恢复也没错；但统一恢复更安全（比如外层还可能要复跑）。写代码时别在这留个「看起来漏了撤销」的口子，面试官会盯。
- **`defer` 恢复行不行？** 行，但每层一个闭包，性能差，不推荐。
- **递归深度会不会爆栈？** `L ≤ 15`，不会；但被追问「word 长度 10^5」时要答改成显式栈迭代。

###### 【加分拓展】
- **这题能不能记忆化？** **不能**，而且这是最容易被答错的点：状态不是 `(i, j, k)`，而是 `(i, j, k) + 已访问集合`。同一个 `(i,j,k)` 在不同访问集合下结论不同，所以没有可复用的子问题——**它和普通网格 DP 的本质区别就在这**。能主动说出这一点，比背模板加分多。
- **频次剪枝为什么正确？** 路径上每个格子只能用一次，所以 word 中某字符出现次数 ≤ board 中该字符总数，是必要条件（不充分，所以只用来提前 false）。
- **反转 word 为什么安全？** 若存在路径 `p0→pL-1`，反向走 `pL-1→p0` 同样合法，所以匹配 word 与匹配 reverse(word) 等价。

```go
type Trie struct {
    children [26]*Trie
    word     string // 非空表示此处是一个完整单词
}

func findWords(board [][]byte, words []string) []string {
    root := &Trie{}
    for _, w := range words {
        node := root
        for _, c := range w {
            idx := c - 'a'
            if node.children[idx] == nil {
                node.children[idx] = &Trie{}
            }
            node = node.children[idx]
        }
        node.word = w
    }
    m, n := len(board), len(board[0])
    res := []string{}
    var dfs func(i, j int, node *Trie)
    dfs = func(i, j int, node *Trie) {
        if i < 0 || i >= m || j < 0 || j >= n {
            return
        }
        c := board[i][j]
        if c == '#' {
            return
        }
        next := node.children[c-'a']
        if next == nil {
            return
        }
        if next.word != "" {
            res = append(res, next.word)
            next.word = "" // 去重，避免同一单词被多次加入
        }
        board[i][j] = '#'
        dfs(i+1, j, next)
        dfs(i-1, j, next)
        dfs(i, j+1, next)
        dfs(i, j-1, next)
        board[i][j] = c
    }
    for i := 0; i < m; i++ {
        for j := 0; j < n; j++ {
            if root.children[board[i][j]-'a'] != nil {
                dfs(i, j, root)
            }
        }
    }
    return res
}
```

##### 一、先看清这是什么问题

这个翻译直接决定了三个技术选择：

| 性质 | 推论 |
|---|---|
| 问「存在性」，不是「最短」 | **BFS 不合适**。BFS 的固定访问标记（visited）是「第一次到某格就是最优」，但这题允许同一格被不同路径经过，固定标记会错误剪掉合法路径 |

| 需要「试一步 → 失败 → 退回来换方向」 | **回溯（DFS + 撤销）** 是唯一自然模型 |

> 这题**不能用记忆化**。它和「网格 DP」（比如 LC 64 最小路径和）的根本区别就在这——后者状态只是坐标，前者状态带集合。

###### 版本 1：教学版（visited 数组，先正确）

```go
func exist(board [][]byte, word string) bool {
	m, n := len(board), len(board[0])
	visited := make([][]bool, m)
	for i := range visited {
		visited[i] = make([]bool, n)
	}

	var dfs func(i, j, k int) bool
	dfs = func(i, j, k int) bool {
		if i < 0 || i >= m || j < 0 || j >= n {
			return false
		}
		if visited[i][j] || board[i][j] != word[k] {
			return false
		}
		if k == len(word)-1 {
			return true
		}
		visited[i][j] = true
		for _, d := range [4][2]int{{0, 1}, {0, -1}, {1, 0}, {-1, 0}} {
			if dfs(i+d[0], j+d[1], k+1) {
				visited[i][j] = false // 早退也要撤销
				return true
			}
		}
		visited[i][j] = false
		return false
	}

	for i := 0; i < m; i++ {
		for j := 0; j < n; j++ {
			if dfs(i, j, 0) {
				return true
			}
		}
	}
	return false
}
```

**这版已经能 AC**（`m,n ≤ 6`，随便过）。它的价值是：逻辑干净，把「标记 / 撤销」的骨架摆清楚了。

##### 三、正式版逐行精讲

```go
func exist(board [][]byte, word string) bool {
	m, n := len(board), len(board[0])
	L := len(word)
```

**`m, n, L` 三个量全程复用**。别看这点小，递归里反复算 `len(word)` 是白给的常数开销。

```go
	var cnt [128]int
	for i := 0; i < m; i++ {
		for j := 0; j < n; j++ {
			cnt[board[i][j]]++
		}
	}
```

**剪枝 ① 的前置：统计 board 的字符频次。** 用 `[128]int`（`byte` 值域）而不是 `map`——数组寻址比哈希快一个量级，而且零分配。这是 Go 里字符计数的标准写法。

```go
	need := cnt
	for i := 0; i < L; i++ {
		if need[word[i]] == 0 {
			return false
		}
		need[word[i]]--
	}
```

**剪枝 ①（频次剪枝）：为什么正确？**
路径上每格只能用一次，所以「word 中字符 `c` 出现次数 ≤ board 中 `c` 的总数」是存在的**必要条件**。不满足就直接 false。

注意这里 `need := cnt` 是**值拷贝**（数组是值类型），后面 `need[word[i]]--` 不会污染 `cnt`——因为剪枝 ② 还要用未消耗的 `cnt`。这是 Go 数组语义的一个小陷阱，写成切片就会出错。

> 这个剪枝在真实用例里收益巨大：大量构造用例是「word 里某字母重复 5 次，但 board 只有 2 个」，裸 DFS 要搜爆才失败，这里 O(mn) 直接秒杀。

```go
	if cnt[word[L-1]] < cnt[word[0]] {
		b := []byte(word)
		for i, j := 0, L-1; i < j; i, j = i+1, j-1 {
			b[i], b[j] = b[j], b[i]
		}
		word = string(b)
	}
```

**剪枝 ②（反向起点）：为什么正确？**
若存在路径 `p0 → p1 → … → p_{L-1}` 匹配 word，那么反向走 `p_{L-1} → … → p0` 同样合法，匹配的是 reverse(word)。**两者等价**。

**为什么有效？** 外层双重循环会把每个格子都当起点调一次 `dfs`，但只有字符等于 `word[0]` 的格子才会往下走。如果 `word[0]` 是 `'e'`（board 里有 5 个），而 `word[L-1]` 是 `'z'`（board 里只有 1 个），反转后起点候选从 5 个降到 1 个——直接砍掉 80% 的搜索树根。

**注意**：这里直接改 `word` 变量是安全的，因为 `dfs` 内部统一引用 `word`。如果代码里某处缓存了原始 `word`，就会出错。

```go
	dx := [4]int{0, 0, 1, -1}
	dy := [4]int{1, -1, 0, 0}

	var dfs func(i, j, k int) bool
	dfs = func(i, j, k int) bool {
		if i < 0 || i >= m || j < 0 || j >= n || board[i][j] != word[k] {
			return false
		}
```

【逐行理解】`if` 这一行同时拦掉**三种情况**：
1. 越界
2. 字符不匹配
3. **撞到已标记的 `'#'`**（`'#' != word[k]`，自动成立）

第 3 点就是复杂度里 `3^L` 的来源：父格被标成 `'#'` 后，回走的那一步在这里就被剪掉了，所以每层虽然写了 4 个方向，实际只有 **3 个有效分支**。

```go
		if k == L-1 {
			return true
		}
```

【逐行理解】匹配完最后一个字符才算成功。**必须放在标记之前**——否则最后一个字符被标成 `'#'` 后直接 return，虽然本题不影响结果，但逻辑上「找到就返回」应当在「占用资源」之前。

```go
		board[i][j] = '#'
		for d := 0; d < 4; d++ {
			if dfs(i+dx[d], j+dy[d], k+1) {
				board[i][j] = word[k]
				return true
			}
		}
		board[i][j] = word[k]
		return false
	}
```

【逐行理解】三个动作要一起看：

- **标记**：`board[i][j] = '#'`
- **撤销**：`board[i][j] = word[k]`。注意恢复成 `word[k]` 而不是用临时变量 `tmp` 存——因为入口那行已经确认 `board[i][j] == word[k]`，原值就是它。省一个变量、省一次栈空间分配。
- **提前返回也要撤销**：成功路径上其实不用撤销（已经全局 return 了），但**统一恢复**是纪律。一旦哪天外层还要复用 board（比如 LC 212 收集多个单词），漏掉这里就是 bug。面试官会盯这个位置。

**为什么不用 `defer`？** `defer func(){ board[i][j] = word[k] }()` 每层递归都挂一个闭包，`L=15` 时是十几倍的函数调用开销。显式恢复更快。

```go
	for i := 0; i < m; i++ {
		for j := 0; j < n; j++ {
			if dfs(i, j, 0) {
				return true
			}
		}
	}
	return false
}
```

【逐行理解】外层枚举起点。可以加 `if board[i][j] == word[0]` 再调，省掉一次函数调用；但 `dfs` 入口已经判了，收益很小，看个人风格。

| 2 | C | (0,2) | `#` | 右邻 |
| 3 | C | (1,2) | `#` | 下邻（(0,3)='E' 不符，换方向） |
| 4 | E | (2,2) | `#` | 下邻（(1,1)='F'、(1,3)='S' 都不符） |
| 5 | D | (2,1) | 不标记 | 左邻，`k == L-1` → **返回 true** |

沿途四个方向的失败尝试都会被自动撤销——比如 `(2,2)` 试左邻 `(2,1)`='D' 时若不匹配 `'E'`，会立即返回并在 `(2,2)` 的循环里试下一个方向。

**对比示例 3 `"ABCB"`**：`(0,0)A → (0,1)B → (0,2)C` 后要 `'B'`，右邻 `(0,3)='E'`、下邻 `(1,2)='C'`、左邻 `(0,1)` 已被标记为 `'#'`，全部失败 → 撤销 `(0,2)`、撤销 `(0,1)`、撤销 `(0,0)`，回到最外层试下一个起点，最终 false。

##### 五、复杂度推导

设 `m`、`n` 为网格行列数，`L = len(word)`。

###### 时间：`O(m·n·3^L)`

- 外层起点：`m·n` 个
- 每个起点展开一棵深度为 `L-1` 的树
- 每层最多 3 个**有效**分支（第 4 个方向是父格，被标记成 `'#'`，在入口就 return 了）
- 每层内部都是 `O(1)` 操作

所以单起点 `O(3^(L-1))`，总上界 `O(m·n·3^L)`。

**常见误区**：说成 `4^L`，或者把起点也当成一次 4 分支。严格算第一个格子的 4 个邻居都有效，是 `4·3^(L-2)`，渐近仍是 `3^L` 量级。

**剪枝的实际影响**：理论上界不变，常数和实际搜索树规模大幅缩小。频次剪枝对一些用例是直接降到 `O(mn)`。

###### 空间：`O(L)`

只有递归栈，深度 `L`，每层常数个变量。

如果用版本 1 的 `visited`，是 `O(m·n)`；用 `defer` 会额外增加栈帧。

| # | 错误 | 后果 | 修正 |

| 1 | 忘记撤销（或撤销写成再标记一次 `'#'`） | 第一个起点跑完后 board 残留 `'#'`，后续起点全部误判 → **WA** | 每个 return 前都要恢复；统一在循环后 + 早退前各恢复一次 |

##### 七、进阶：LC 212 单词搜索 II（几乎是必考后续）

题目：board 不变，但给一个**单词列表** `words`，返回所有能在 board 中找到的词。

###### 为什么不能「每个词跑一遍 LC 79」

`k` 个词各跑一次是 `O(k·m·n·3^L)`，`k` 大时爆炸。而且这些词**共享大量前缀**，逐词搜索等于把公共前缀重复搜索了 `k` 遍。

###### 正解：把 words 建成 Trie，DFS 同时沿网格和 Trie 走

一次 DFS 就能同时推进「所有以当前网格路径为前缀的单词」。

```go
type Trie struct {
	children [26]*Trie
	word     string // 非空表示此处结束一个完整单词
}

func findWords(board [][]byte, words []string) []string {
	root := &Trie{}
	for _, w := range words {
		node := root
		for i := 0; i < len(w); i++ {
			idx := w[i] - 'a'
			if node.children[idx] == nil {
				node.children[idx] = &Trie{}
			}
			node = node.children[idx]
		}
		node.word = w
	}

	m, n := len(board), len(board[0])
	res := []string{}

	var dfs func(i, j int, node *Trie)
	dfs = func(i, j int, node *Trie) {
		if i < 0 || i >= m || j < 0 || j >= n {
			return
		}
		c := board[i][j]
		if c == '#' {
			return
		}
		next := node.children[c-'a']
		if next == nil {
			return // Trie 里没有这个前缀，整条分支剪掉
		}
		if next.word != "" {
			res = append(res, next.word)
			next.word = "" // 去重：同一单词可能被多条路径拼出
		}
		board[i][j] = '#'
		dfs(i+1, j, next)
		dfs(i-1, j, next)
		dfs(i, j+1, next)
		dfs(i, j-1, next)
		board[i][j] = c
	}

	for i := 0; i < m; i++ {
		for j := 0; j < n; j++ {
			if root.children[board[i][j]-'a'] != nil {
				dfs(i, j, root)
			}
		}
	}
	return res
}
```

###### 和 LC 79 的三个关键差异

1. **不再比较单个字符，而是「沿 Trie 指针走」**。`next == nil` 就是最强剪枝：前缀不存在，后面全白搭。
2. **找到单词后把 `next.word = ""` 清掉**。同一个词可能被多条不同路径拼出来，清空即去重。**但不能 return**——同一个 Trie 节点下面还挂着更长的词（比如找到 `"app"` 时，树里可能还有 `"apple"`）。
3. **复杂度从 `O(k·mn·3^L)` 降到 `O(mn·3^L)`**（`L` 为最长词长）。因为所有词的前缀搜索被合并成了一棵树。

> **加分点**：如果 `words` 里有很多短词、且 board 很小，可以反过来把 board 建成 Trie 再遍历 words？不划算——board 无法枚举路径。业界主流就是「words 建 Trie」，这是唯一正确方向。

它的用途是判断算法**有没有白干**：

- 下界：至少要写 1430×16 个字符，逃不掉
- 实际：你的回溯搜索树节点数正好和答案数同阶，没有多余搜索

### 🤖 助手

**因为 n 对括号一共 2n 个位置，每个位置两种选法（左或右），所以总共 2^(2n) = 4^n 种串。**

`4^n` 是「**完全不管合法性**、把所有括号串全列出来」的规模。合法性检查（前缀左括号 ≥ 右括号）只是在 4^n 这个池子里挑，而它砍掉的只是多项式级的量，指数底数 4 不变。

##### 从 4^n 到 4^n/n^1.5 的两刀

| 步骤 | 剩下多少 | 为什么 |
|---|---|---|
| 全部串 | `4^n` | 2n 个位置，每位 2 选 |
| 只留「n 个左 + n 个右」（平衡串） | `C(2n,n) ≈ 4^n/√n` | 从 4^n 个串里挑出用了 n 个左括号的，这是二项式系数中间项 |
| 只留合法的（前缀左 ≥ 右） | `C(2n,n)/(n+1) ≈ 4^n/n^1.5` | 平衡串里恰好有 1/(n+1) 的比例合法（卡特兰数的定义式） |

所以完整链条是：

```
4^n   ←── 每位 2 选，指数底数 4 的来源
 ↓ ÷√n    改为"平衡串"
 ↓ ÷n     改为"合法串"
4^n / n^1.5   ≈ 4^n / √n（题解习惯写法）
```

##### 关键直觉

**为什么砍了两刀底数还是 4？** 因为两刀砍的都是多项式因子，没伤到指数。

- 「平衡」这一刀是概率论里的正态分布峰值：2n 次抛硬币恰好 n 次正面的概率约 `1/√(πn)`——只按 `√n` 衰减
- 「合法」这一刀是 `1/(n+1)`——只按 n 衰减

指数项 `4^n` 原封不动，只是被除以 `n^1.5`。**只要约束是「局部、多项式级」的，指数底数就不会变**——这是回溯题里判断复杂度的通用规律：`2n` 个位置各 2 选就是 `4^n`，剪枝只改多项式因子。

```
C_8 = 1430           实际合法答案
```
