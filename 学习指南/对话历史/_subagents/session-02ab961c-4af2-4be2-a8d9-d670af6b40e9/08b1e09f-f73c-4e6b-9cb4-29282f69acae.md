##### 一句话结论

这里只有一个 bug，位置在 `partition` 的循环条件：`for m < j` 少了等号，应该是 `for m <= j`。

问题在于 `j` 在 else 分支里用作“待处理区最右端（含）”，但循环条件却按“右端（不含）”来写。这两种定义混在一起，导致 `nums[j]` 可能一次都没有被比较过，却被调用方当成“等于 pivot 区”永久跳过。这个 bug 不会 panic，也不会死循环，只会结果错，而且随机化让它时好时坏。

---

##### 为什么 `j` 的语义矛盾

【逐行理解】对照 else 分支：

```go
}else{
    nums[j],nums[m]=nums[m],nums[j]
    j--          // 这里：把“最右端的待处理元素”换到 m 处，右边界左移一格
}
```

`j--` 的写法说明 `j` 是“最后一个还没分类的下标”，也就是闭区间右端。既然 `j` 本身也是待处理位置，循环就必须处理 `m == j` 那一格，所以条件是 `m <= j`。

用 `m < j` 的后果：

- 扫描中若从未触发过 else（一路 `<` 或 `==`），则 `m` 会一路增长到等于 `j`，此时循环直接退出，`nums[j]` 从头到尾没被读过；
- 而 `partition` 返回 `(i, j)`，调用方的语义是 `[i, j]` 为等于区，`quick` 只递归 `[lo, i-1]` 和 `[j+1, hi]`；
- 于是，这个没被检查过的 `nums[j]` 被当作“等于 pivot”排除在递归之外，再也不会参与比较，最终永久错位。

触发条件很具体：本次扫描没有出现 `> pivotval` 的元素，并且 `nums[hi] < pivotval`。

##### 手推一个会错的例子

`nums = [2,1,1]`，第一层随机到 `pivot = lo`（即选中 index 0，概率 1/3）：

```
pivotval = 2, i=0, m=1, j=2
nums[1]=1 < 2  → swap(0,1) → [1,2,1], i=1, m=2
m < j ? 2 < 2 假 → 退出
返回 (i,j) = (1,2)
```

返回后 `[1,2]` 被当成等于区（其实 `nums[2]=1` 是小于区），只递归 `quick(0,0)` 和 `quick(3,2)`，两者都不做事。

结果 `[1,2,1]`，没排好。而 `nums[2]` 那个 `1` 自始至终一次都没被比较过。

##### 修法（二选一，别混着用）

【必记】**方案 A（最小改动）**：保留 `j = hi` 和 `j--` 的闭区间语义，只把循环条件补上等号：

```go
for m <= j {     // 唯一改动
```

此时结束时 `m == j+1`，`[i, j]` 恰好是等于区，`return i, j` 和 `quick(lo,i-1)/quick(j+1,hi)` 全部保持不变。`nums[lo]` 那个 pivot 副本会一直待在 `i` 位，被 swap 反复“挤”到 `[i, m-1]` 里，所以 `[i, j]` 确实是纯等于区，边界自洽。

【必记】**方案 B**：若坚持 `m < j`，那 `j` 必须改成“大于区左边界”的开区间语义，三处一起改：

```go
i, m, j := lo, lo+1, hi+1   // j 初值 +1
...
}else{
    j--                      // 先减
    nums[j], nums[m] = nums[m], nums[j]
}
...
return i, j - 1              // 返回值也要跟着变
```

现在你的代码是“方案 A 的初值和返回值 + 方案 B 的循环条件和 else 顺序”，取了两边的错位组合。

##### 顺带建议

【理解】**随机化反而成了这个 bug 的掩护**。`pivot` 随机，同一份输入可能这次对下次错，跑几百个用例还能通过。排这类区间边界 bug，最有效的方法是固定几个小数组手工推一遍（`[2,1,1]`、`[2,3,4]`、`[1,1,1]`、`[2,1]`），而不是加大数据量。

【略读】修好后复杂度不变：期望时间 `O(n log n)`（n 为数组长度），最坏 `O(n²)`（pivot 每次取到极值，随机化后概率极低）；空间期望 `O(log n)` 递归栈，最坏 `O(n)`。三路分区在“大量重复元素”输入下是 `O(n)`，这是它在 912 上比普通二分快排稳的原因。

【略读·加分】可以把“先递归较小的那一半”加上去，把最坏栈深压到 `O(log n)`：

```go
if i-lo < hi-j { quick(lo,i-1); quick(j+1,hi) } else { quick(j+1,hi); quick(lo,i-1) }
```

面试里问“三路快排为什么能抗重复元素”和“边界怎么定”时，标准答法是**三要素必须自洽：j 的初值 = j 在 swap 中的用法 = 返回值给调用方的区间语义**。你这段就是典型反例，面试官很喜欢拿这种“少个等号”的写法考人。

##### 二路 Lomuto 为什么必须换

二路快排里 `i` 是“小于区右开边界”，代表一个**待填的空位**：`lo` 位置被 pivot 占着，但语义上 `lo` 应该属于小于区，于是整个扫描过程中 `lo` 一直是个临时的存放位置。循环结束后：

- `[lo, i-1]` 全 `< p`
- `[i, hi]` 全 `≥ p`
- pivot 仍然在 `lo` 位置

此时 `swap(nums[lo], nums[i])` 一次操作完成两件事：把 pivot 送到分界点 `i`，把 `i` 那个 `≥ p` 的元素挪到 `lo` 填补空位。**pivot 的最终位置只能靠这次交换来确定**，不换就无法定位。

##### 三路为什么不用换，以及换了为什么会错

三路里 `i` 不再是空位，它是**等于区的左端点**。三个不变量如下：

```
[lo, i-1] < p      [i, m-1] == p      [j+1, hi] > p
```

关键在初始状态：`i = lo, m = lo+1`，此时 `[i, m-1] = [lo, lo]`，长度是 1，**这唯一一个元素就是 `nums[lo]`，它的值正是 pivotval**。等于区在循环开始前就已经存在了，并非尚未建立。

再看 `m - i` 这个长度怎么变化：

| 分支 | 动作 | `m - i` |
|---|---|---|
| `<` | `i++` 且 `m++` | 不变 |
| `==` | `m++` | **+1**（等于区扩张）|
| `>` | `j--`，i/m 不动 | 不变 |

初始 `m - i = 1 > 0`，而之后只增不减，所以 **`m - i ≥ 1` 恒成立**，也就是“等于区永远非空、`nums[i]` 的值永远是 pivotval”。这一行就是整个问题的答案。

于是对于 `<` 分支，它做的是把 `i` 位置上那个“等于值”换到 `m`、然后双指针同步右移，等于值被向右移动，`i` 处换成新来的小值。**pivot 元素被一路向右移动，但始终留在 `[i, m-1]` 这间“等于区”里。** 循环结束时 `[i, j]` 整段都等于 pivotval，pivot 元素就在其中，它的位置并不需要单独确定。

现在看如果强行补上 `swap(nums[lo], nums[i])`：

- 若 `i == lo`（一个 `<` 元素都没有）：自交换，无害但也没用。
- 若 `i > lo`：由不变量，`nums[lo]` 此刻是一个 **小于 pivotval** 的值，`nums[i]` 是一个**等于 pivotval** 的值。这一交换等于把一个小值塞进等于区、把一个等于值扔进小于区，使得 `[lo, i-1] < p` 和 `[i, j] == p` 同时失效。调用方拿到返回值 `(i, j)` 后会把那个小值当“已归位的等于值”跳过，**最终结果直接出错**。

所以这并非“多余步骤”，它的效果是在正确结果上**注入一个错误**。二路和三路在这一步上有本质区别。

##### 一个类比

二路快排像“给一个人安排座位”：pivot 是唯一主角，你必须亲自把他领到座位上，所以有收尾那个 swap。

三路快排像“按颜色分三堆站队”：pivotval 是“等于堆”的登记标准，它一开始就站在等于堆的区域内，并且始终在那里，整堆人自动聚拢。你不需要再去安排某个人，堆形成了，他自己就在堆里。

所以三路 `partition` 返回的是**两个下标** `(i, j)`，也就是给一整段定位；二路只返回**一个下标**，也就是给一个元素定位。返回值的差异，本质就是“归位责任”落点的差异。

---

【必记】**判断标准**：只要 `partition` 返回的区间是“等于区 `[i, j]`”，就一定不需要收尾交换；只要返回的是“pivot 的单一落点”，就一定有收尾交换。

##### 改完为什么仍然正确

Lomuto 的循环不变式是：`[lo, i-1]` 存放**已比较过且满足条件**的元素，`i` 是它们的下一个空位，`[i, j-1]` 存放不满足条件的元素。

循环结束后执行 `swap(nums[i], nums[hi])`：

| 写法 | 循环后状态 | 交换后 |
|---|---|---|
| `<` | `[lo,i-1]` 严格小，`[i,hi-1]` 大于等于 | `[lo,i-1]` 小，`[i]`=pivot，`[i+1,hi]` 大于等于 |
| `<=` | `[lo,i-1]` 小于等于，`[i,hi-1]` 严格大 | `[lo,i]` 小于等于，`[i+1,hi]` 严格大 |

两边的“小于等于区 / 大于区”都成立了，`i` 处也确实换成了 pivotval，返回 i 后递归 `[lo,i-1]`、`[i+1,hi]` 都合法，**不会死循环，也不会越界**。所以你说“行不行”，答案是行。

##### 它到底改变了什么

只改变了一件事：**值等于 pivotval 的元素去了哪一边**。

- 用 `<`：划分成 `小 | 大等于`，等值元素全落进**右侧**递归区间；
- 用 `<=`：划分成 `小等于 | 大`，等值元素全落进**左侧**递归区间。

两边都只是把等值元素从一边挪到另一边，**没有任何一方把它们“拎出来”并从递归中剔除**。这正是关键：三路快排之所以能抗重复元素，是因为 `partition` 返回 `(i, j)` 一段区间，等于区**不进入递归**；而 Lomuto 无论怎么写，都只返回一个下标，等于 pivot 的元素永远得继续参与后面的分区。

所以面对全相等的数组 `[1,1,1,...,1]`：

- `<`：`i` 一步不动，返回 lo，右区间规摸 n-1，递归 n 次 → `O(n²)`；
- `<=`：`i` 冲到 hi，返回 hi，左区间规模 n-1，递归 n 次 → 同样 `O(n²)`。

**两者一样退化。** 想真正解决，只能换三路（或双路 Hoare 变体），改条件符号这种手段并不解决根本问题。

---

##### 真正需要注意的两个问题

【必记】**问题一：`i` 位置必须存放“已经比较过”的元素。** Lomuto 的正确性完全依赖这一点。因此 pivot 必须放在 **hi**，并且循环只能扫描 `lo..hi-1`；你贴的 `j < hi` 正好符合。如果 pivot 是换到 `lo` 的，那 `j := lo; j < hi` 就会把 `nums[hi]` 完全漏掉，**和你上一轮三路快排那个“少个等号”是同一类 bug**（边界元素没被比较，被当成已归位永久跳过）。回头务必确认你的 pivot 落在 hi 还是 lo。

【理解】**问题二：`<=` 会让 `j == i` 时出现无意义的自交换**（`swap(nums[i], nums[i])`），不影响结果，但说明代码没有区分“值小于 pivot”和“值等于 pivot”这两件事。Lomuto 本来就不区分，用哪个符号都行，但别把这种模糊当成优化。

##### 面试考点

【高频变形原题】Lomuto 循环不变式是什么、为什么收尾必须 `swap(i, hi)`、为什么 pivot 要排除在循环之外。这三个问题的答案其实是一条：pivot 是“哨兵”，它占着 hi 却不参与比较，收尾交换同时完成“pivot 归位”和“把 i 处那个大于等于 pivot 的元素挪到 hi”。

##### 结论

如果 pivot 取最左侧元素 `nums[lo]`，那么分区收尾时要执行 `swap(nums[lo], nums[i])`。这一步要求**相遇点 i 上的值 ≤ pivot**。先移动 j 正好能保证这一点；如果先移动 i，相遇点可能是大于 pivot 的值，这个值会被换到 lo，进而导致整个分区错误。

更根本地说：**规则是“先移动与 pivot 相对的那一侧”**，并非永远“先动 j”。pivot 在左侧就应先动右指针，pivot 在右侧则要先动左指针。

##### 为什么先动 j 就能保证

先看两个内层循环的停止条件（假设 pivot 在 lo）：

```go
for i < j && nums[j] >= pivot { j-- }   // j 停下时：nums[j] < pivot
for i < j && nums[i] <= pivot { i++ }   // i 停下时：nums[i] > pivot
```

关键在错误写法中容易被忽略的一点：**两个守卫都是 `i < j`，所以 i 和 j 相邻时，“先动的那一方”会直接移动到对方的位置并停下。**

那么，双方相遇后，这个位置上的值是谁留下的？

- 如果 **j 先移动**，它最终会移动到 i 的位置；此时 i 位置的值是**上一轮交换后由 j 放进去的小值**，或者是初始的 `nums[lo]`，也就是 pivot 本身。因此相遇点 ≤ pivot，`swap(lo,i)` 安全。
- 如果 **i 先移动**，它最终会移动到 j 的位置；此时 j 位置的值是**上一轮交换后由 i 放进去的大值**，或者初始的 `nums[hi]`。因此相遇点可能 > pivot，`swap(lo,i)` 会把大值放到最左，分区就失效了。

用一句话概括：**j 停下时带来“小于 pivot”的属性，i 停下时带来“大于 pivot”的属性；收尾交换需要的是前者，所以要让 j 成为最后移动的那一个。**

---

##### 反例手推一下（`nums = [2,1,3]`，pivot = 2）

**先动 j（正确）：**

```
j: nums[2]=3 >= 2 → j=1；nums[1]=1 < 2 → 停
i: nums[0]=2 <= 2 → i=1；i==j 停
相遇 i=j=1，nums[1]=1 < 2 ✔
swap(0,1) → [1,2,3]，递归两侧都空 → 正确
```

**先动 i（错误）：**

```
i: nums[0]=2 <= 2 → i=1；nums[1]=1 <= 2 → i=2；i==j 停（j 一步没动）
相遇 i=j=2，nums[2]=3 > 2 ✘
swap(0,2) → [3,1,2]，返回 2
左区间 [0,1] 再排成 [1,3]
最终 [1,3,2] —— 错的
```

这里错误的原因是：i 一路向右移动，把 j 挤在末尾没有机会移动，最终停在完全没验证过相对大小的 `nums[hi]=3` 上。

注意，这种错误并不会每次出现。比如 `[5,3,4]` 用先动 i 的写法恰好也能排对（因为 pivot 是最大值，落点正好在最右）。这和上一轮“随机化掩盖 bug”一样：顺序写反了，错误只会在**特定大小关系**下暴露，测试不容易抓到。

| pivot 位置 | 先动谁 | 收尾交换 | 需要相遇点满足 |
|---|---|---|---|
| `nums[lo]` | 先动 j（右） | `swap(lo, i)` | `nums[i] ≤ pivot` |
| `nums[hi]` | **先动 i（左）** | `swap(i, hi)` | `nums[i] ≥ pivot` |

判断方法就是看收尾要满足什么不等式，再找一个停止条件能提供该不等式的那一侧指针，让它最后移动。

顺带说明：**Hoare 1961 年的原始版本没有这个讲究**。它取中间元素作 pivot、用 do-while 且不带 `i<j` 守卫、返回的是 j 而不是 i，递归区间是 `(lo, j)` 和 `(j+1, hi)`。面试里常说的“为什么先走右边”特指“pivot 取最左 + 收尾 swap(lo,i)”这种民间变体。

---

##### 注意事项与面试考点

【必记】**守卫必须是 `>=` / `<=`，不能写成 `>` / `<`。** 全等数组时，如果把内层条件写成 `nums[j] > pivot { j-- }`，i、j 都不会移动，外层 `i<j` 永远成立且没有交换，会**直接死循环**。带等号至少能保证指针必然前进。

【高频变形原题】“手写快排时为什么先移动右指针”是极高频追问，标准答案就是“收尾交换要求相遇点 ≤ pivot，而 j 的停止条件恰好提供这个性质”。

【实现层追问】该写法的两个退化场景要能说出来：① 有序数组 + 固定取 lo 作 pivot → `O(n²)`（每次返回 lo，只削掉一个元素）；② 全等数组（即使有 `>=` 守卫）→ j 一路移动到 i，返回 lo，同样 `O(n²)`。随机化只解决前者，重复元素必须通过三路分区解决。

【加分拓展】挖坑法（把 pivot 存进临时变量、先移动右指针填补 lo 的空位）之所以也是“先动右”，原因相同：空位在左，就要从右取料。把“先动哪侧”归结到“空位、落点在哪侧”这一层，比背诵“先动 j”更不容易记反。

复杂度照旧：分区 `O(n)`；整体期望 `O(n log n)`、最坏 `O(n²)`（n 为数组长度）；空间是递归栈，期望 `O(log n)`、最坏 `O(n)`。
