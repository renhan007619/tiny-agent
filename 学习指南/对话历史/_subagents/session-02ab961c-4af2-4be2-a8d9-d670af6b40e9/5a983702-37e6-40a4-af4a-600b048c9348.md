##### 一句话结论

这里只有一个 bug，位置在 `partition` 的循环条件：`for m < j` 少了等号，应该是 `for m <= j`。

问题在于 `j` 在 else 分支里用作“待处理区最右端（含）”，但循环条件却按“右端（不含）”来写。这两种定义混在一起，导致 `nums[j]` 可能一次都没有被比较过，却被调用方当成“等于 pivot 区”永久跳过。这个 bug 不会 panic，也不会死循环，只会结果错，而且随机化让它时好时坏。

---

##### 为什么 `j` 的语义矛盾

【逐行理解】对照 else 分支：

```go
}else{
    nums[j],nums[m]=nums[m],nums[j]
    j--          // 这里：把“最右端的待处理元素”换到 m 处，右边界左移一格
}
```

`j--` 的写法说明 `j` 是“最后一个还没分类的下标”，也就是闭区间右端。既然 `j` 本身也是待处理位置，循环就必须处理 `m == j` 那一格，所以条件是 `m <= j`。

用 `m < j` 的后果：

- 扫描中若从未触发过 else（一路 `<` 或 `==`），则 `m` 会一路增长到等于 `j`，此时循环直接退出，`nums[j]` 从头到尾没被读过；
- 而 `partition` 返回 `(i, j)`，调用方的语义是 `[i, j]` 为等于区，`quick` 只递归 `[lo, i-1]` 和 `[j+1, hi]`；
- 于是，这个没被检查过的 `nums[j]` 被当作“等于 pivot”排除在递归之外，再也不会参与比较，最终永久错位。

触发条件很具体：本次扫描没有出现 `> pivotval` 的元素，并且 `nums[hi] < pivotval`。

---

##### 手推一个会错的例子

`nums = [2,1,1]`，第一层随机到 `pivot = lo`（即选中 index 0，概率 1/3）：

```
pivotval = 2, i=0, m=1, j=2
nums[1]=1 < 2  → swap(0,1) → [1,2,1], i=1, m=2
m < j ? 2 < 2 假 → 退出
返回 (i,j) = (1,2)
```

返回后 `[1,2]` 被当成等于区（其实 `nums[2]=1` 是小于区），只递归 `quick(0,0)` 和 `quick(3,2)`，两者都不做事。

结果 `[1,2,1]`，没排好。而 `nums[2]` 那个 `1` 自始至终一次都没被比较过。

---

##### 修法（二选一，别混着用）

【必记】**方案 A（最小改动）**：保留 `j = hi` 和 `j--` 的闭区间语义，只把循环条件补上等号：

```go
for m <= j {     // 唯一改动
```

此时结束时 `m == j+1`，`[i, j]` 恰好是等于区，`return i, j` 和 `quick(lo,i-1)/quick(j+1,hi)` 全部保持不变。`nums[lo]` 那个 pivot 副本会一直待在 `i` 位，被 swap 反复“挤”到 `[i, m-1]` 里，所以 `[i, j]` 确实是纯等于区，边界自洽。

【必记】**方案 B**：若坚持 `m < j`，那 `j` 必须改成“大于区左边界”的开区间语义，三处一起改：

```go
i, m, j := lo, lo+1, hi+1   // j 初值 +1
...
}else{
    j--                      // 先减
    nums[j], nums[m] = nums[m], nums[j]
}
...
return i, j - 1              // 返回值也要跟着变
```

现在你的代码是“方案 A 的初值和返回值 + 方案 B 的循环条件和 else 顺序”，取了两边的错位组合。

---

##### 顺带建议

【理解】**随机化反而成了这个 bug 的掩护**。`pivot` 随机，同一份输入可能这次对下次错，跑几百个用例还能通过。排这类区间边界 bug，最有效的方法是固定几个小数组手工推一遍（`[2,1,1]`、`[2,3,4]`、`[1,1,1]`、`[2,1]`），而不是加大数据量。

【略读】修好后复杂度不变：期望时间 `O(n log n)`（n 为数组长度），最坏 `O(n²)`（pivot 每次取到极值，随机化后概率极低）；空间期望 `O(log n)` 递归栈，最坏 `O(n)`。三路分区在“大量重复元素”输入下是 `O(n)`，这是它在 912 上比普通二分快排稳的原因。

【略读·加分】可以把“先递归较小的那一半”加上去，把最坏栈深压到 `O(log n)`：

```go
if i-lo < hi-j { quick(lo,i-1); quick(j+1,hi) } else { quick(j+1,hi); quick(lo,i-1) }
```

面试里问“三路快排为什么能抗重复元素”和“边界怎么定”时，标准答法是**三要素必须自洽：j 的初值 = j 在 swap 中的用法 = 返回值给调用方的区间语义**。你这段就是典型反例，面试官很喜欢拿这种“少个等号”的写法考人。

##### 结论

**在整段排序中，真正需要归位的是“等于 pivotval 这一整段元素”，并非“nums[lo] 那个具体元素”。在三路快排里，这段从 lo 开始就已经成型，`nums[lo]` 的值本身就是 pivotval，所以它一定在这段里。**

**而且这里不能加那个 swap：加了会直接破坏分区。** 这与二路快排“可加、但多余”的情况不同。原因在于 `i` 的语义完全变了。

---

##### 二路 Lomuto 为什么必须换

二路快排里 `i` 是“小于区右开边界”，代表一个**待填的空位**：`lo` 位置被 pivot 占着，但语义上 `lo` 应该属于小于区，于是整个扫描过程中 `lo` 一直是个临时的存放位置。循环结束后：

- `[lo, i-1]` 全 `< p`
- `[i, hi]` 全 `≥ p`
- pivot 仍然在 `lo` 位置

此时 `swap(nums[lo], nums[i])` 一次操作完成两件事：把 pivot 送到分界点 `i`，把 `i` 那个 `≥ p` 的元素挪到 `lo` 填补空位。**pivot 的最终位置只能靠这次交换来确定**，不换就无法定位。

##### 三路为什么不用换，以及换了为什么会错

三路里 `i` 不再是空位，它是**等于区的左端点**。三个不变量如下：

```
[lo, i-1] < p      [i, m-1] == p      [j+1, hi] > p
```

关键在初始状态：`i = lo, m = lo+1`，此时 `[i, m-1] = [lo, lo]`，长度是 1，**这唯一一个元素就是 `nums[lo]`，它的值正是 pivotval**。等于区在循环开始前就已经存在了，并非尚未建立。

再看 `m - i` 这个长度怎么变化：

| 分支 | 动作 | `m - i` |
|---|---|---|
| `<` | `i++` 且 `m++` | 不变 |
| `==` | `m++` | **+1**（等于区扩张）|
| `>` | `j--`，i/m 不动 | 不变 |

初始 `m - i = 1 > 0`，而之后只增不减，所以 **`m - i ≥ 1` 恒成立**，也就是“等于区永远非空、`nums[i]` 的值永远是 pivotval”。这一行就是整个问题的答案。

于是对于 `<` 分支，它做的是把 `i` 位置上那个“等于值”换到 `m`、然后双指针同步右移，等于值被向右移动，`i` 处换成新来的小值。**pivot 元素被一路向右移动，但始终留在 `[i, m-1]` 这间“等于区”里。** 循环结束时 `[i, j]` 整段都等于 pivotval，pivot 元素就在其中，它的位置并不需要单独确定。

现在看如果强行补上 `swap(nums[lo], nums[i])`：

- 若 `i == lo`（一个 `<` 元素都没有）：自交换，无害但也没用。
- 若 `i > lo`：由不变量，`nums[lo]` 此刻是一个 **小于 pivotval** 的值，`nums[i]` 是一个**等于 pivotval** 的值。这一交换等于把一个小值塞进等于区、把一个等于值扔进小于区，使得 `[lo, i-1] < p` 和 `[i, j] == p` 同时失效。调用方拿到返回值 `(i, j)` 后会把那个小值当“已归位的等于值”跳过，**最终结果直接出错**。

所以这并非“多余步骤”，它的效果是在正确结果上**注入一个错误**。二路和三路在这一步上有本质区别。

---

##### 一个类比

二路快排像“给一个人安排座位”：pivot 是唯一主角，你必须亲自把他领到座位上，所以有收尾那个 swap。

三路快排像“按颜色分三堆站队”：pivotval 是“等于堆”的登记标准，它一开始就站在等于堆的区域内，并且始终在那里，整堆人自动聚拢。你不需要再去安排某个人，堆形成了，他自己就在堆里。

所以三路 `partition` 返回的是**两个下标** `(i, j)`，也就是给一整段定位；二路只返回**一个下标**，也就是给一个元素定位。返回值的差异，本质就是“归位责任”落点的差异。

---

【必记】**判断标准**：只要 `partition` 返回的区间是“等于区 `[i, j]`”，就一定不需要收尾交换；只要返回的是“pivot 的单一落点”，就一定有收尾交换。

【实现层追问】**面试中常被追问**：“三路快排能不能像 Lomuto 那样在末尾 swap 一下？” 正确回答：`i == lo` 时无害，`i > lo` 时会破坏分区，因为 `lo` 位置此时存的是小于值，并非 pivot。能答到“破坏 `[lo,i-1] < p` 不变量”这一层就足够了。

【加分拓展】三路的优势是：等于区不再进入递归，所以全相同元素时只有一次分区，时间 `O(n)`、栈 `O(1)`；二路在全相同时退化成 `O(n²)`。这也是 912 排序数组里三路更稳的原因。
