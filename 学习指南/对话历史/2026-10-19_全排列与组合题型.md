核心区别：

**全排列（排列）**：
- 输出长度固定 = n（所有元素都要用）
- 顺序有意义：`[1,2]` 和 `[2,1]` 不同
- 每层决策：从"还没用过的元素"里挑一个 → 需要 used[] 数组或交换法
- 树的深度 = n，宽度逐层递减（n, n-1, n-2...）
- 叶子节点数 = n!，终止条件 depth == n
- 去重：`[1,1,2]` 全排列需要 sort + used[i] && i>0 && nums[i]==nums[i-1] && !used[i-1]

**组合**：
- 输出长度不固定（或固定 k），元素顺序无意义：`[1,2]` 和 `[2,1]` 算同一个
- 每层决策：从"当前位置之后"的元素里挑 → 传 start 下标，保证不回头
- 树的深度 ≤ n，宽度递减
- 终止条件：path 长度 == k（或按需收集）
- 去重：sort + i>start && nums[i]==nums[i-1] 跳过

**关键一句话**：排列靠 used 标记"谁还没用"，组合靠 start 标记"下一步从哪开始"。本质都是"选或不选"的决策树，区别只在于"可选集合"怎么定义。

再深入一层：这两者的统一视角 = 决策树上的「候选集」如何收缩：

- 排列：候选集 = 全集 - 已用（收缩靠 used）
- 组合：候选集 = [start, n)（收缩靠 start 单调递增）
- 子集：候选集同组合，但每个节点都收集（不只是叶子）
- 组合总和/分割：候选集 = [start, n)，但带 sum 剪枝
- 排列 II：候选集 = 全集 - 已用 + 同层去重

**统一模板**（这类题型的通用骨架）：

```
func backtrack(start, path) {
    if 满足终止条件 { 收集; return }
    for i := start; i < n; i++ {
        // 1. 剪枝
        // 2. 做选择（path append, used[i]=true）
        // 3. 递归 backtrack(i+1 或 0)
        // 4. 撤销
    }
}
```

决策点只有两个：
1. **下一层的候选范围**是 `i+1`（组合/子集）还是 `0`（排列，配 used）
2. **收集结果的位置**是叶子（排列/组合定长）还是每个节点（子集）

**复杂度**：
- 全排列：时间 O(n × n!)，空间 O(n)（递归栈+used，不算结果集）
- 组合 C(n,k)：时间 O(k × C(n,k))，空间 O(k)
- 子集：O(n × 2^n)

**对比解法**：
- 排列：字典序下一个排列（next_permutation）O(n) 单次，可以迭代产生全部 O(n×n!) 无递归；或者 STL 风格。面试中回溯更通用。

##### 一句话结论

**排列和组合的差别，不在“回溯写法”上，而在“下一个候选元素从哪来”上：**

- **排列**：每层从“还没用过的元素”里挑，也就是“全集减去已用”，候选集合是**散开**的，所以必须用 `used[]` 做标记
- **组合**：每层从“当前下标之后的元素”里挑，也就是 `start` 单调递增，候选集合是**一段连续区间**，所以必须传 `start`

其余部分（做选择、递归、撤销选择、收集答案、剪枝）**完全一样**。所以真正的做法不是分别记住两套模板，而是看出它们其实是同一个模板的两个参数调整。

##### 一、从决策树看区别

以 `nums = [1,2,3]` 为例：

**组合 C(3,2)**：每层只能往右走，不能回头
```
[]
├─ [1] ─┬─ [1,2] ✓
│       └─ [1,3] ✓
├─ [2] ─── [2,3] ✓
└─ [3] （后面没数了，走不下去）
```

**排列 P(3)**：每层能跳到任意一个“还没被占”的元素
```
[]
├─ [1] ─┬─ [1,2] ── [1,2,3] ✓
│       └─ [1,3] ── [1,3,2] ✓
├─ [2] ─┬─ [2,1] ── [2,1,3] ✓
│       └─ [2,3] ── [2,3,1] ✓
└─ [3] ─┬─ [3,1] ── [3,1,2] ✓
        └─ [3,2] ── [3,2,1] ✓
```

关键差异就在 `[1,3]` 这个节点：**在组合里它已走到底，因为 2 在左边、被 start 排除掉了；在排列里它还要能拿 2，因为 2 只是“还没被用”**。所以排列无法用一个单调递增的下标来管理候选元素，只能显式记录谁被用了。

**判断该用哪一套标准：**

| 问题 | 判断依据 |
|---|---|
| 输出元素顺序算不算不同 | 算 → 排列；不算 → 组合 |
| 结果长度是否固定为 n | 是 → 排列；≤ n → 组合或子集 |
| 能不能重复取同一元素 | 能 → 组合里 `start` 传 `i`（不是 `i+1`） |

##### 二、统一模板：只有两个可调参数

```
backtrack(状态) {
    if (终止条件) { 收集; return }        // ← 旋钮2：叶子收集还是每层收集
    for i := 起点; i < n; i++ {            // ← 旋钮1：起点怎么定
        剪枝
        path = append(path, nums[i])
        backtrack(新状态)
        path = path[:len-1]                // 撤销
    }
}
```

**可调参数 1：候选起点**

| 题型 | 起点 | 配套 |
|---|---|---|
| 组合、组合总和（不可重） | `i+1` | 无 |
| 组合总和（可重） | `i` | 无 |
| 子集 | `start = i+1` | 无 |
| 排列 | `0` | **必须配 `used[]`** 跳过已用元素 |

**可调参数 2：在哪一层收集**

| 题型 | 收集位置 |
|---|---|
| 组合（定长 k）、排列 | 只有**叶子**（`len(path)==k` 或 `==n`） |
| 子集 | **每个节点**都收（含空集），进入函数第一行就 `收集` |

也就是说：**子集、组合、组合总和、分割回文串其实共用一个骨架**，只调整起点和收集时机；**排列、全排列 II 共用另一个骨架（配 used）**。这就是“这类题型”的真正归类方式。

##### 三、复杂度（n 的含义见下）

| 题型 | 时间 | 空间（不含结果集） |
|---|---|---|
| 排列 | `O(n · n!)` | `O(n)` 递归栈 + `used` + `path` |
| 全排列 II（含重复） | 上界同上，实际少 | `O(n)` |
| 组合 C(n,k) | `O(k · C(n,k))` | `O(k)` |
| 子集 | `O(n · 2^n)` | `O(n)` |
| 组合总和 | `O(S)` 搜索树节点数，剪枝后远小 | `O(target/min)` 最深 |

n 是候选元素个数。时间复杂度里多出来的那个因子，是**每个叶子要把 `path` 复制一次**（Go 里 `append` 到结果集必须 `copy`，否则共享底层数组，这是之前踩过的坑，不过这里仍要再提一次）。

【值得记】写复杂度时写成“搜索树节点数 × 每节点工作量”最稳，面试官问“为什么有 n!”就是问叶子数。

##### 四、对比解法与取舍（面试可能考察的第二种写法）

**排列**
- 回溯 + `used[]`：通用，能处理重复元素，推荐
- 交换法：`swap(nums[depth], nums[i])` → 递归 `depth+1` → 换回来。省掉 `used` 数组，但**排序后去重逻辑会乱**（原数组顺序被破坏），所以 LC47 别用；而且交换法本质上是用“数组前缀”替代 used，和 used 法等价
- 字典序迭代 `next_permutation`：单次 `O(n)`，从当前排列推下一个；适合“求下一个排列”或“只要第 k 个排列”；求全部时总复杂度同回溯但常数小、无递归栈
- 康托展开：排列 ↔ 整数双向映射，`O(n²)` 或 `O(n log n)`，冷门但能吹

**组合**
- 回溯 + `start`：标准
- 二进制枚举：n ≤ 20 时，用 `mask` 枚举所有子集再筛大小，写起来快但没法剪枝，且 n 一大就废
- 递推/DP：只要**数量**不要**具体方案**时用 `C(n,k)=C(n-1,k-1)+C(n-1,k)`，或者 LC39 求方案数用完全背包

【值得记】判别口诀：**要输出所有具体方案 → 回溯；只要个数 → DP/数学**。LC39（求组合数）和 LC39 变形（求组合方案）是同一题的两个版本，面试常拿来对照。

##### 五、面试可能问的点（按真实度分层）

**【高频变形原题】**
- LC46 全排列、LC47 全排列 II
- LC77 组合、LC39/40 组合总和
- LC78/90 子集、LC131 分割回文串、LC93 复原 IP
- LC491 递增子序列（特例：**不能排序**，去重得用 `map` 记本层用过的值）

**【实现层追问】**
1. **排列为什么不能只传 `start` 不用 `used`？**
   因为排列的候选集不连续，`[1,3]` 之后还需要 `2`，而 `start` 只能往后走。这是最高频的追问。
2. **树层去重 vs 树枝去重**
   全排列 II 里 `!used[i-1]` 是**树层去重**（同层相同元素只取第一个），`used[i-1]` 是树枝去重（同一路径上重复）。两者都能过 LC47，但树层去重是通用写法。**记这条：同层去重看“前一个相同元素在本层有没有被选”，树枝去重看“有没有在路径上”。**
3. **组合里 `i+1` 和 `i` 的区别**
   元素能否重复使用。LC39 传 `i`（可重），LC40 传 `i+1`（不可重）。
4. **剪枝公式怎么来的**
   `for i := start; i <= n-(k-len(path)); i++`：还差 `k-len(path)` 个元素，从 `i` 到末尾还有 `n-i` 个，要 `n-i >= k-len(path)`，移项即得。**这是组合题唯一值得背的公式**。
5. **回溯的“撤销”为什么必须和“做选择”严格对称**
   递归返回时状态要恢复到进 for 之前，否则下层污染上层。Go 里 `path = path[:len-1]` 和 `used[i]=false` 都得写。

**【加分拓展】**
- 全排列的字典序迭代：从右找第一个升序对 → 找右边第一个比它大的 → 交换 → 反转后缀
- 回溯 = DFS 遍历决策树，**剪枝 = 提前 return**，复杂度分析就是数树节点
- 去重的统一框架：**先排序，再“同层跳过”**，区别只在“同层”怎么定义（组合看 `i > start`，排列看 `!used[i-1]`）——把这条抽象出来，所有去重题（40/47/90/491）都套得上

##### 可选优化：把 isValid 从 O(n) 降到 O(1)

每次放棋子都要扫三个方向，是冗余的。改用三个标记数组，**放 Q 时打标、撤销时清标**，冲突判断变 O(1)：

```go
var (
	colUsed, diag1, diag2 []bool   // diag1: 左上-右下 (row-col+n); diag2: 右上-左下 (row+col)
)
```

在 `dfs(cur)` 的 for 里：

```go
if !colUsed[i] && !diag1[cur-i+n] && !diag2[cur+i] {
	colUsed[i], diag1[cur-i+n], diag2[cur+i] = true, true, true
	chessboard[cur][i] = "Q"
	dfs(cur + 1, n)
	chessboard[cur][i] = "."
	colUsed[i], diag1[cur-i+n], diag2[cur+i] = false, false, false
}
```

**【值得记】** 两个对角线下标公式：
- 主对角（左上→右下）：`row - col` 恒定，加 `n` 偏移防负
- 副对角（右上→左下）：`row + col` 恒定

这是 n 皇后最常被追问的优化点，面试答「用三个 bool 数组把冲突检测降到 O(1)」基本就满分了。

**两者的信息量完全相等**，都是 n×n 个字符。只是 `chessboard` 把格子拆开，`temp` 把每行粘成一个字符串。题目要求返回 `[][]string`，内层每个 `string` 代表一行，所以必须转成 `temp` 这种形状。

```
[0] ["Q",".","."]  ──Join("")──▶  "Q.."  ──▶  [0]
```

##### 为何要新建 temp 复制，而不能直接 append chessboard

这才是这段代码真正的动机。`chessboard` 是**一块可反复修改的工作画布**，搜索过程中每放一个 Q、每撤销一个 Q，都在修改它。如果直接 `res = append(res, chessboard)`：

```go
res = append(res, chessboard)   // ❌ 存进去的是"画布地址"，不是棋盘内容
```

`append` 进 `res` 的只是切片的**头部描述**（指针、长度、容量），它指向的还是同一块底层数组。之后搜索继续修改画布：

```
时刻1：找到解A，棋盘 = ┌Q..┐    res[0] ──┐
                       │...Q│             ├─▶ 同一块内存
                       └.Q..┘             │
时刻2：回溯后棋盘变成   ┌....┐    res[0] ──┘  ← 跟着一起变了！
                       │....│
                       └....┘
最后：res 里所有元素显示的都是"最后一盘棋"，前面的解全被覆盖
```

所以必须先复制成 `temp`：`temp` 里的每个 `string` 在 Go 里都是**不可变**的，复制完成后，它与画布再无关联。之后无论怎么修改 `chessboard`，`temp` 都保持不变。

**【值得记】** 一句话：
> **回溯里「入结果集」存的必须是快照，不是引用。** 棋盘、`path`、`[]byte` 全是同一回事——`path` 要 `copy`，棋盘要 `Join` 成字符串（或逐行复制），本质都是**在结果集里保存值，而不是保存指针**。

`Join` 在这里顺便充当了「深拷贝」：它把 n 个格子的内容读出来拼成新字符串，读出来的那一刻就是一次完整复制。

##### `strings.Join(v, "")` 详解

**签名**：

```go
func Join(elems []string, sep string) string
```

**语义**：把 `elems` 里所有元素，**两两之间插入 `sep`**，拼成一个字符串。注意是插在**元素之间**，开头和结尾不加。

**你的调用**：`v = ["Q", ".", "."]`，`sep = ""`

```
元素:   "Q"        "."        "."
sep:         ""         ""
结果:   "Q" + "" + "." + "" + "."  =  "Q.."
```

**对比 `sep` 不同时的效果**（理解 sep 最直观的方式）：

| `v` | `sep` | 结果 |
|---|---|---|
| `["Q",".","."]` | `""` | `"Q.."` |
| `["Q",".","."]` | `","` | `"Q,.,."` |
| `["Q",".","."]` | `"-"` | `"Q-.-."` |
| `["abc","def"]` | `"--"` | `"abc--def"` |

所以传 `""` 就是「无分隔符直接首尾相接」，这正是把一行格子连成一个字符串所需的。

**为什么元素是 `string` 一行才能 Join**：`Join` 只接受 `[]string`。你的 `chessboard` 是 `[][]string`，正好每行 `v` 是 `[]string`，直接传进去。如果棋盘建成 `[][]byte`，就得先 `string(v)` 转换（`[]byte` → `string` 可以直接转，但 `[]string` 不行）。

**内部实现（了解即可）**：`Join` 内部先算总长度，`strings.Builder.Grow` 一次性预分配，再循环写入。所以它是一次分配、O(总字符数) 时间。

**对比 `+` 拼接（值得记的坏习惯）**：

```go
s := ""
for _, c := range v {
    s += c   // ❌ 每轮都新建一个字符串并复制前面所有内容
}
```

n=8 时差别看不出来，但它是 O(n²)。`Join` 是 O(n)。**面试问「你怎么把 []string 拼成一个字符串」时，答 `strings.Join` 是加分点，答 `+=` 会被追问复杂度。**

**时间复杂度的分析方法论：**

核心思想：**时间复杂度 = 递归树的节点数 × 每个节点的工作量**。

具体步骤：
1. 画出/想象递归树：有几种节点、多深、每层多少
2. 数节点数（或叶子数 + 内部节点数）
3. 算每个节点做多少事
4. 相乘

对 subsets：
- 递归树：每个节点代表一个"部分子集"，深度最多 n
- 树的节点数 = 2^n（每个元素选/不选）+ 减去……
- 实际上这棵树的节点数：所有子集的个数 = 2^n（含空集），边数 = 2^n - 1
- 每个节点（在 for 循环里）做的工作：append O(1) 均摊，copy O(len(path)) ≤ O(n)

所以总时间 = Σ(每个子集复制它的长度) = Σ_{k=0}^{n} C(n,k)·k = n·2^{n-1}

这个是精确值：Σ k·C(n,k) = n·2^{n-1}。

所以时间复杂度 O(n·2^n)。而不是 O(2^n)！

但注意：LeetCode 官方对 78 的复杂度常写 O(n × 2^n)，因为结果集本身有 n×2^{n-1} 个元素（所有子集的元素总数 = n·2^{n-1}），必须输出这么多，所以这是**输出下界**，无法更优。

4. **temp 复制**：每次 O(n)，但同时只存在一份，O(n)（不算结果集）

##### 先给结论

| | 你这题的复杂度 |
|---|---|
| **时间** | `O(n · 2^n)`，精确是 `n·2^(n-1) + 2^n` 量级 |
| **辅助空间**（不含返回值） | `O(n)`：递归栈深 n + `path` 长 n |
| **总空间**（含 `res`） | `O(n · 2^n)` |

**重点是：这里不是 `O(2^n)`，而是 `O(n·2^n)`。** 下面解释为什么，以及递归复杂度到底该怎么一步步算。

---

##### 一、递归复杂度怎么分析：先分形态，再选工具

**递归题不能一律套公式。** 先判断递归属于哪一类：

| 形态 | 特征 | 分析方法 | 例子 |
|---|---|---|---|
| **分治** | 每层问题规模缩小（n → n/2） | 写出递推式 `T(n)=aT(n/b)+f(n)`，用**主定理** | 归并排序、二分 |
| **枚举/回溯** | 每层枚举分支，**没有重复子问题** | **数搜索树的节点数 × 每节点工作量** | 子集、排列、组合、n 皇后 |
| **DP** | 有大量**重复**子问题 | **状态数 × 单状态转移代价** | 背包、LIS |

你这题属于**枚举型**，所以用第二套工具。**不要去找递推式**——回溯题的递归树不是「一个 n 的问题拆成 2 个 n/2 的问题」，而是「一棵把答案全枚举出来的树」，写不出 `T(n)=...` 那种式子。

---

##### 二、枚举型的三步法（这是真正可复用的方法）

###### 第 1 步：数搜索树有多少节点

**节点 = 一个「部分解」= `path` 的一次取值。**

`dfs` 每进入一次，树上就多一个节点；`for` 每迭代一次，就往下走一条边。

- 子集：每个元素「选/不选」→ 节点数 **`2^n`**（含空集）
- 组合 C(n,k)：只看叶子 → **`C(n,k)`** 个
- 排列：**`n!`** 个叶子

**顺手记一个关系**：回溯树里 **`for` 迭代总次数 ≈ 节点数**，因为每次迭代对应一条边，边数 = 节点数 − 1。很多分析错误就在这——把循环开销漏了。

###### 第 2 步：数每个节点干多少活

逐行看 `dfs` 里每次迭代做的事：

```go
path = append(path, nums[i])                // O(1) 均摊
dfs(nums, i+1)                              // 递归，不计入本层
temp := make([]int, len(path))              // ← O(k)，k 是当前 path 长度
copy(temp, path)                            // ← O(k)
res = append(res, temp)                     // O(1) 均摊
path = path[:len(path)-1]                   // O(1)
```

**这里最关键的发现：每次收集要 `O(k)`，k 是当前子集的长度，不是 O(1)。**

###### 第 3 步：求和（加权，不是简单相乘）

因为单节点代价随深度变化，不能直接「节点数 × 常数」，要**按长度分组求和**：

- 长度 k 的子集有 `C(n,k)` 个
- 每个复制代价 `O(k)`

```
总复制代价 = Σ(k=0→n) C(n,k) · k
```

用组合恒等式 `k·C(n,k) = n·C(n-1,k-1)`：

```
Σ C(n,k)·k = n · Σ C(n-1,k-1) = n · 2^(n-1)
```

**所以时间是 `O(n·2^n)`，不是 `O(2^n)`。** 这个 n 是「每个答案平均长度 n/2」摊出来的，跑不掉。

---

##### 三、为什么这个 n 跑不掉（面试最爱追问的点）

**【高频】问：能不能优化到 `O(2^n)`？**

**不能。** 因为**答案本身**就有 `n·2^(n-1)` 个整数：

```
n = 3：子集共 8 个，元素总数 = 3·4 = 12 个
      [] (0) [1](1) [2](1) [3](1) [1,2](2) [1,3](2) [2,3](2) [1,2,3](3) → 0+1+1+1+2+2+2+3 = 12 ✓
```

**任何算法都必须输出这 12 个数，`O(n·2^n)` 就是输出量的下界。** 这个性质叫**输出敏感性（output-sensitive）**：算法复杂度不能低于输出规模。

所以：

- 如果题目要求返回所有子集 → `O(n·2^n)` 已经最优，没有改进空间
- 如果只要求**返回子集个数** → 才是 `O(1)`（直接 `1<<n`）

**【值得记】** 一句话记住：
> **回溯题的时间复杂度，先看「答案总大小」，再看「搜索树节点数 × 节点代价」，两者取大。**

---

##### 四、空间怎么算：三件套分开说

**空间必须分成三块算，混在一起就一定算错：**

| 部分 | 大小 | 说明 |
|---|---|---|
| ① 递归栈 | `O(n)` | 最深 n+1 层，每层只存几个局部变量 |
| ② `path` 底层数组 | `O(n)` | 最多存 n 个数（Go 的 append 扩容，cap 最终到 n 量级） |
| ③ `res` 结果集 | `O(n·2^n)` | 2^n 个切片，每个平均 n/2 个 int |
| ④ `temp` | `O(n)` | 每层一份，但同时只活着一份，不累加 |

**所以两种口径：**

- **辅助空间（不含返回值）= ① + ② + ④ = `O(n)`** ← 面试通常问这个
- **总空间（含返回值）= `O(n·2^n)`** ← 严格讲这个

**面试必须主动说明用哪个口径**，否则容易被判错。标准答法：「辅助空间 O(n)，主要是递归栈和 path；如果算上必须返回的结果集，是 O(n·2^n)，这部分是题目要求的输出，逃不掉。」

**【值得记】** 空间三件套的口诀：
> **栈深 × 每帧大小，加上显式容器，再加上输出（单独说）。**

| 你的 n 皇后 | `O(n!)` 节点 | `isValid` `O(n)` + 收集 `O(n²)` | `O(n!·n²)` | `O(n²)` |

**规律看出来了没**：只有「复制/检查」是 `O(1)` 的题，时间才等于节点数；一旦每节点要扫一遍 `path` 或棋盘，就多乘一个因子。

---

##### 六、你这题的两个额外提醒

**① 收集位置在递归返回之后，所以你才需要手动补空集**

```go
dfs(nums,0)
res=append(res,[]int{})   // 手动补
```

因为你的收集写在「子递归返回后」，而 `[1]` 这种状态是在它自己那层循环末尾才收集的，空集没有对应的「边」，只能手动补。

**更标准的写法是把收集挪到函数开头**（进入即收集，代表"当前 path 就是一个子集"）：

```go
func dfs(nums []int, start int) {
    temp := make([]int, len(path))
    copy(temp, path)
    res = append(res, temp)      // 每个节点都收，含空集
    for i := start; i < len(nums); i++ {
        path = append(path, nums[i])
        dfs(nums, i+1)
        path = path[:len(path)-1]
    }
}
```

这样 `res=append(res,[]int{})` 就不用写了。**复杂度完全一样**（还是 `O(n·2^n)`），只是把「叶子收集」改成「节点收集」，代码更干净。

**② Go 里的内存细节（了解即可）**

`res` 是 `[][]int`，每个元素是一个切片头（24 字节：指针+len+cap）。所以 `res` 真实占用 ≈ `2^n × 24 + n·2^(n-1) × 8` 字节。n=20 就上 GB 了——**这就是为什么子集题通常 `n ≤ 10`**，不是算法慢，是答案装不下。

- LC78 子集、LC90 子集 II、LC46/47 全排列、LC77 组合

**【实现层追问】**
1. 「子集的时间复杂度？」→ 答 `O(n·2^n)`，**并主动解释为什么不是 `O(2^n)`**（这是分水岭）
2. 「空间复杂度？递归栈算不算？」→ 答「辅助 O(n)，算输出 O(n·2^n)」

4. 「`copy` 那两行能不能省？」→ 不能，省了就是共享底层数组，所有答案变成同一个（之前聊过的 `temp` 快照问题）

- **输出敏感性**：复杂度不能低于输出规模，这是理论下界
- **主定理 vs 枚举树**：能主动说出「回溯题不适用主定理，因为递归树是枚举树不是分治树」，会显得你不是背答案

> **递归复杂度 = 先看形态（分治用主定理 / 枚举数树 / DP 数状态），枚举型按「节点数 × 节点代价」加权求和，最后拿「答案总大小」兜底取大；空间分「栈 + 容器 + 输出」三块。**

|---|---|
| **时间** | `O(n · n!)` |
| **辅助空间**（不含返回） | `O(n)`：递归栈 + `path` + `used` |

##### 一、数搜索树节点

**第 k 层（`path` 长度为 k）有 `P(n,k) = n!/(n−k)!` 个节点**，每层依次少一个可选元素：

```
第0层：1 个          （空 path）
第1层：n 个          （选了第 1 个数）
第2层：n(n−1) 个     （选了前 2 个）
...
第k层：n!/(n−k)! 个
...
第n层：n! 个          ← 叶子，每个是一个完整排列
```

n = 4 时数一遍：

```
k:   0    1    2    3    4
节点: 1    4   12   24   24    总 = 65
```

**【值得记】** 总节点数 `Σ(k=0→n) n!/(n−k)! = n!(1 + 1 + 1/2! + 1/3! + ...) ≈ e·n!`

n=4 验算：`e × 24 ≈ 65.2`，和上面数的 65 对上。所以**节点数是 `O(n!)`，常数约 2.718**，不是 `n!` 的几倍那么粗略，而是精确的 `e·n!`。

每次 `for` 迭代 = 一条边 = 一次 `append` / `used` 赋值，都是 `O(1)`。

**搜索部分开销 = 节点数 × O(1) = `O(n!)`。**

---

##### 二、加上复制开销

`if len(path) == n` 那个分支里：

```go
temp := make([]int, n)
copy(temp, path)      // ← O(n)，且只有叶子才进来
```

**只有 n! 个叶子各复制一次，每次 n 个元素**，所以：

```
复制总代价 = n! × n = n·n!
```

n=4 验算：24 个叶子 × 4 = 96 次元素写入。而搜索部分只有 65 次节点访问，所以**复制是主导项**。

**总时间 = `O(n!) + O(n·n!) = O(n·n!)`。**

##### 三、为什么不是 `O(n!)`（面试必问）

答案个数是 `n!`，但**每个答案本身长 n**，所以：

```
答案里的元素总数 = n! × n = n·n!
```

任何算法都得把这 `n·n!` 个数字写进返回的切片里。**`O(n·n!)` 就是输出量的下界，无法优化。**

对比一下思路：

| 题目怎么问 | 答案 |
|---|---|
| 返回**所有排列**（LC46） | `O(n·n!)`，最优，不可改进 |
| 只返回**排列个数** | `O(1)`（数学上直接 `n!`） |
| 返回**第 k 个排列**（LC60） | `O(n²)` 康托展开，不是搜索 |

**【值得记】** 一句话：**“搜索开销”和“输出开销”哪个大取哪个。全排列里输出开销 `n·n!` 压倒了搜索开销 `n!`，所以写 `O(n·n!)`。**

##### 四、空间三件套

| 部分 | 大小 |
|---|---|
| ① 递归栈 | `O(n)`（深度 n+1，每帧常数） |
| ② `path` | `O(n)` |
| ③ `used []bool` | `O(n)` |
| ④ `res` 结果集 | `O(n·n!)`（n! 个切片 × 每个 n 个 int） |
| ⑤ `temp` | `O(n)`，同时只活一份 |

- **辅助空间 = ①+②+③+⑤ = `O(n)`** ← 面试通常问这个
- **总空间 = 加上 ④ = `O(n·n!)`**

标准答法：「辅助空间 `O(n)`，递归栈和 path、used 各 `O(n)`；如果算上必须返回的结果集是 `O(n·n!)`，那是题目要求的输出。」

##### 五、对比解法：同样 `O(n·n!)`，但常数和空间不同

**① 交换法（swap）**

```go
for i := depth; i < n; i++ {
    nums[depth], nums[i] = nums[i], nums[depth]
    dfs(depth + 1)
    nums[depth], nums[i] = nums[i], nums[depth]
}
```

- 时间：同样是 `O(n·n!)`（每次交换 `O(1)`，叶子复制 `O(n)`）
- 空间：**省掉了 `used` 的 `O(n)`**，但递归栈还是 `O(n)`，**数量级不变**
- **致命缺点**：原数组顺序被破坏。排序去重逻辑失效，所以 **LC47（含重复元素）不能用交换法**，必须用 `used`

**② 字典序迭代（`next_permutation`）**

- 单次推进 `O(n)`
- 求全部：`O(n·n!)`，但**没有递归栈**，空间降到 `O(n)`（一个数组）
- 求「下一个排列」（LC31）或「第 k 个排列」（LC60）时比回溯快得多

**③ 只要个数 / 第 k 个**

- 个数：`n!`，`O(1)`
- 第 k 个：康托展开，`O(n²)` 或配树状数组 `O(n log n)`

**【值得记】** 面试时被问「还有别的解法吗」，能说出「排列的迭代法 + 康托展开」就够了；说「交换法更省空间」要补一句「但处理重复元素很麻烦」，否则会被追问。

##### 六、全排列 II（LC47）的复杂度

结构上有重复元素，但：

- **上界不变**：最坏情况（元素全不同）仍是 `O(n·n!)`
- **实际更小**：剪枝跳过了大量重复分支
- **空间不变**：`used` + 排序额外 `O(n)`（排序是 `O(n log n)`，被主导项淹没）

所以面试答「上界 `O(n·n!)`，剪枝后实际远小于上界」即可。

##### 七、面试考点分层

**【高频变形原题】**
- LC46 全排列、LC47 全排列 II、LC31 下一个排列、LC60 第 k 个排列
- **复杂度追问几乎必问**，尤其「为什么带个 n」

**【实现层追问】**
1. **「为什么 `O(n·n!)`？」** → n! 个答案，每个长度 n，输出下界就是 n·n!
2. **「空间 `O(n)` 还是 `O(n²)`？」** → 辅助 O(n)，含输出 O(n·n!)，两种口径说清楚
3. **「交换法能省什么？」** → 省 used 的 O(n)，但栈还是 O(n)，且不能去重
4. **「节点数到底多少？」** → `e·n!`，能说出 `Σ n!/(n−k)!` 这个式子会加分

**【加分拓展】**
- **输出敏感性**：`O(n·n!)` 不可改进，因为答案本身就这么大
- **康托展开**：排列 ↔ 整数的双向映射，`O(n²)` 定位第 k 个排列
- **`next_permutation` 算法**：从右找升序对 → 找右边第一个更大 → 交换 → 反转后缀
- **全排列无重复元素时，n! 个答案里每个位置出现每个元素恰好 `(n−1)!` 次**——这是为什么康托展开能工作的理论依据

> **搜索 `O(n!)`（树节点 `e·n!`），复制 `O(n·n!)`（n! 个叶子 × 长 n），取大得 `O(n·n!)`；空间辅助 `O(n)`，含输出 `O(n·n!)`。那个 n 来自「每个答案必须被完整复制出来」，是输出下界，删不掉。**

<details>
<summary>🧠 思考过程</summary>

用户问：如果不用"答案总大小"这条捷径，怎么单独分析"搜索树节点数 × 节点代价"这条路径？也就是说，对全排列，怎么从递归树的角度算出 O(n·n!) 或至少 O(n!)。

这是好问题。用户想知道：能不能完全独立地从树的角度推导，不靠"输出下界"。

答案是：**能，而且能得到同样的结果甚至更精确的结论**。因为搜索树分析里已经包含了"节点代价"这一项，而复制代价就是节点代价的一部分。

关键是：**回溯的时间 = Σ_节点 (该节点的循环迭代数 × 每次迭代常数代价) 汇总，其实就是 Σ_边 的代价**。

具体方法：

**第一步：给树的每个"层"定义节点数和单节点代价**

对全排列：
- 第 k 层的节点数（path 长 k）= P(n,k) = n!/(n-k)!
- 第 k 层每个节点的 for 循环迭代次数 = (n-k)（已用 k 个，剩 n-k 个候选）
- 所以第 k 层产生的子节点数 = P(n,k) × (n-k) = P(n,k+1) ✓ 自洽

**第二步：把"节点代价"拆成两部分**
1. **结构代价**：for 循环的迭代（每条边 = 一次 append / 一次 used 赋值）→ O(1) per 边
2. **结算代价**：叶子处的复制（每个叶子 O(n)）

**第三步：分层求和**

边总数 = 节点总数 - 1 = Σ_{k=0}^{n-1} P(n,k)·(n-k) = Σ_{k=1}^{n} P(n,k) ≈ e·n!

具体 n=4：
- k=0: 1 个节点 × 4 次迭代 = 4
- k=1: 4 × 3 = 12
- k=2: 12 × 2 = 24
- k=3: 24 × 1 = 24
- 总边数 = 64 = 65 - 1 ✓

复制：24 个叶子 × 4 = 96

总 = 64 + 96 = 160 次操作，主导项 n·n! = 96。

**关键洞察**：为什么"节点数 × 节点代价"能推出 O(n·n!)？
- 节点数是 O(n!)
- 节点代价不是常数！它是 O(n)（叶子处复制 n 个元素）
- 所以 O(n!) × O(n) = O(n·n!)

用户可能卡在"节点代价"这个词上——以为它是常数。要点明：**节点代价是"平均/最坏每个节点的工作量"，它可以是 n 的函数**。

更严谨的写法：T = Σ_节点 cost(节点)。如果 cost(节点) 最大是 O(n)，节点数 O(n!)，那么 T = O(n!·n)。这是**上界**，不需要精确。

但更精确：只有叶子是 O(n)，内部节点是 O(1)。所以：
T = O(节点数 × 1) + O(叶子数 × n) = O(n!) + O(n·n!) = O(n·n!)

这个分解很重要：**"节点代价"要按节点类型分类，不能一刀切**。

**方法论升级**：
回溯题算时间，公式是
```
T = Σ_{每类节点} 该类节点数 × 该类单节点代价
```

节点通常分两类：
- **内部节点**：做的是 for 循环 + append + 递归调用 → O(分支数) 或 O(1)（如果按边算）
- **叶子节点**：做的是收集答案 → O(答案长度)

于是：
```
T = O(边数) + O(叶子数 × 答案长度)
```

对全排列：边数 O(n!)，叶子 n!，答案长度 n → T = O(n! + n·n!) = O(n·n!)

对子集：节点数 2^n，每个节点都收集，答案长度 ≤ n → T = O(2^n·n) = O(n·2^n)

**【值得记】这个框架最实用**：把节点代价分"内部 O(1)"和"叶子 O(答案长度)"，分别算完相加。

**第三种口径：按层求和（最严谨）**

如果每层代价不同，就写 Σ over 层：
```
T = Σ_{k=0}^{d} (第 k 层节点数) × (第 k 层单节点代价)
```
这里的"单节点代价"指该层每个节点（含它发起的循环）的总开销，包括它产生的所有子节点边——容易重复计数，所以通常用两层结构：节点数 + 边长（边=节点数-1）。

按层求和示例（全排列）：
- 第 k 层节点数 P(n,k)
- 第 k 层每个节点做 (n-k) 次迭代，每次 O(1)
- 复制只在 k=n 层，每个 O(n)

T = Σ_{k=0}^{n-1} P(n,k)(n-k) + P(n,n)·n
  = Σ_{k=1}^{n} P(n,k) + n!·n
  = O(n!) + n·n!

用 n=4 具体数字验证（160）。

**再讲一个陷阱：为什么不能简单"节点数 × 最大节点代价"？**
因为这样会得到 n!·n 的上界，虽然对（O(n·n!) 确实是对的），但如果叶子复制是 O(n) 而内部节点是 O(1)，直接乘会把内部节点也按 O(n) 算，高估了。对全排列两者数量级相同（都是 n·n!），所以看不出来；但对子集：
- 节点数 2^n，最大节点代价 O(n)
- 简单相乘 = O(n·2^n) ✓ 恰好也对（因为每个节点都收集）
- 但对"组合 C(n,k)"：叶子数 C(n,k)，答案长 k，节点数更大（中间节点），简单相乘 C(n,k)·k 会低估？不，节点数 > 叶子数，用节点数乘会更保守。

其实对"内部 O(1) + 叶子 O(n)"的结构：
- 紧确上界 = 节点数·1 + 叶子数·n
- 粗糙上界 = 节点数·n
两者差一个因子 n 吗？节点数·n vs 叶子数·n，如果节点数 >> 叶子数，粗糙上界会高估 n 倍。全排列里节点数 = e·n!，叶子数 = n!，比值 e，所以高估常数倍，不影响数量级。但如果是二叉决策树（子集），节点数 2^n，叶子 2^n，比值 2，也不影响。

所以实际上"节点数 × 最大节点代价"在实践中能给出正确数量级，但严格讲解要说清"分开算更准确"。

**还要回答"如果不用答案总大小"**：
可以完全不用。搜索树分析自洽地给出 O(n·n!)。"答案总大小"只是**快速校验**的捷径，或者说是下界的论证。两者结论一致。

- 答案总大小给的是**下界**（不能低于它）
- 搜索树分析给的是**上界**（算法不会超过它）
- 两者相等 → 紧确

这个逻辑关系讲清楚非常加分：**下界 + 上界 = 紧确界（Θ）**。

这是一个特别好的点。用户问"两条路怎么走"，正确答案是：一条给下界，一条给上界，相等才是 Θ。

##### 先理清两条路的关系

你要的这条分析路线，得到的是**上界**；“答案总大小”得到的是**下界**。

```
搜索树分析 → 算法"最多花多少" → 上界 O(n·n!)
输出规模   → 至少"必须花多少" → 下界 Ω(n·n!)
两者相等   → 紧确界 Θ(n·n!)
```

**所以不用“答案大小”这条捷径，完全能独立推出 `O(n·n!)`**，只是它会给出上界，严格说还要下界才能说明“最优”。面试时先讲树、再补一句“而且这就是输出下界”，最完整。

---

##### 一、关键动作：把「节点代价」拆成两类

先明确：“节点代价”不一定是常数，可以随节点类型变化；直接乘一个固定系数是错的。

回溯树上的节点只有两种：

| 节点类型 | 干什么活 | 代价 |
|---|---|---|
| **内部节点** | `for` 循环挑下一个元素、`append`、递归 | **O(1)**（按边算） |
| **叶子节点** | 收集答案（`make` + `copy` / `Join`） | **O(答案长度)** |

于是时间公式变成：

```
T = O(树的边数)                    ← 内部节点的循环开销
  + O(叶子数 × 每个叶子的答案长度)  ← 收集开销
```

**这个拆法就是你要的“节点数 × 节点代价”的正确用法**——不是用一个平均代价乘总节点数，而是**按节点类型分别乘，再相加**。

---

##### 二、全排列按层求和

全排列的树：第 k 层（`path` 长 k）有 `P(n,k) = n!/(n−k)!` 个节点，第 k 层的每个节点循环迭代 `(n−k)` 次（k 个已用，剩 n−k 个候选）。

**第一块：循环开销（按边算）**

```
第 k 层节点数 × 该层每节点迭代次数 = P(n,k) × (n−k) = P(n,k+1)
```

（这个等式正好说明它等于“下一层的节点数”，自洽）

```
循环总开销 = Σ(k=0→n−1) P(n,k)·(n−k) = Σ(k=1→n) P(n,k) ≈ e·n!
```

**第二块：收集开销**

只有 k=n 那一层进入收集分支：

```
叶子数 = P(n,n) = n!，每个叶子复制 n 个元素
收集总开销 = n! × n
```

**第三块：相加**

```
T = O(n!) + O(n·n!)  →  取最大项  →  O(n·n!)
```

---

##### 三、用 n=4 手算验一遍（数字对上才敢信）

**节点数（每层）：**

| 层 k | 节点数 P(4,k) | 每个节点的迭代次数 | 该层循环开销 |
|---|---|---|---|
| 0 | 1 | 4 | 4 |
| 1 | 4 | 3 | 12 |
| 2 | 12 | 2 | 24 |
| 3 | 24 | 1 | 24 |
| 4 | 24（叶子） | — | 0 |
| **合计** | **65 个节点** | — | **64 次循环** |

- 节点总数 65，`e·4! ≈ 65.2` ✓
- 循环次数 64 = 节点数 − 1 ✓（这就是“边数 = 节点数 − 1”）

**收集开销：** 24 个叶子 × 每个复制 4 个元素 = **96**

**总计：** `64 + 96 = 160` 次基本操作，其中复制占 96/160 = 60%，**是主导项**。

而 `n·n! = 4 × 24 = 96`，正好是复制的量——**说明时间复杂度的 n 完全来自“每个答案都要复制 n 个元素”**。这条分析不靠输出公式也能看到那个 n 从哪来。

---

##### 四、为什么不能直接「节点数 × 一个代价」了事

假设粗暴地写 `节点数 × 最大节点代价`：

```
O(n!) × O(n) = O(n·n!)
```

**结果碰巧对**，因为全排列里“节点数/叶子数 = e ≈ 2.7”是常数倍，内部节点和叶子同阶。但这是运气：

- **内部节点**只花 `O(1)`，把它也按 `O(n)` 算，就**高估了**
- 如果树的内部节点远多于叶子（比如组合题 C(n,k)，k 很小时），这种粗暴估计会高估一个数量级

**判断标准**：

```
叶子数 / 节点数 → 常数  ⇒ 粗估无害，直接相乘
叶子数 = o(节点数)      ⇒ 必须分开算
```

全排列、子集都是“常数比”，可以粗估；组合题最好分开算。

**【值得记】** 一句话：
> **“节点数 × 节点代价”里的节点代价，指“该节点的实际工作量”，不是“全树最大工作量”。不同层、不同类型要分开乘再相加。**

---

##### 五、通用检查清单（四步，任何回溯题都能套）

```
第1步  画树：确定层数、每层节点数的组合表达式（2^n / C(n,k) / P(n,k) / n!）
第2步  分类：哪些节点只做循环（O(1)），哪些节点要收集（O(答案长度)）
       —— 也别忘了有些题每个节点都要调剪枝/校验函数（O(n) 或 O(n²)）
第3步  分别求和：
       循环开销 = 边数 ≈ 节点数
       收集开销 = Σ(每个答案的长度)
       校验开销 = 节点数 × 校验函数代价
第4步  取最大项定阶，写出 Θ（上界+下界都说了就是 Θ）
```

**第 2 步最容易漏**：很多人只数“节点数 × 收集”，漏掉每层循环迭代和每节点的 `isValid`；n 皇后的 `O(n²)` 因子就是这么漏出来的。

##### 六、几道题的“节点代价”对照

| 题 | 节点数 | 内部节点代价 | 叶子/收集代价 | 结果 |
|---|---|---|---|---|
| **全排列** | `e·n!` | `O(1)` | `n! × n` | `O(n·n!)` |
| **子集** | `2^n` | `O(1)` | 每节点都收集 `O(k)` → `ΣC(n,k)·k` | `O(n·2^n)` |
| **组合 C(n,k)** | 大于叶子 | `O(1)` | `C(n,k) × k` | `O(k·C(n,k))` |
| **n 皇后（你的写法）** | `O(n!)` | `isValid O(n)` | 叶子 `O(n²)`（`Join` n 行） | `O(n!·n²)` |
| **n 皇后（bool 数组优化）** | `O(n!)` | `O(1)` | 叶子 `O(n²)` | `O(n!·n²)`，仅搜索部分降为 `O(n!)` |
| **分割回文串** | 指数级 | `isPalindrome O(n)` | 叶子 `O(n)` | `O(n·2^n)` 量级 |

**规律**：`节点数 × 该节点实际工作` 里，只要有一项是 `O(n)` 以上，就会多乘一个因子；全排列是“叶子复制”贡献的 n，n 皇后是“校验+收集”贡献的。

##### 七、面试怎么说（一段话模板）

> “全排列的递归树第 k 层有 `P(n,k)` 个节点，总节点数约为 `e·n!`；内部节点每次只做 `O(1)` 的 append 和 used 标记，所以循环开销 `O(n!)`；叶子有 `n!` 个，每个收集要复制 n 个元素，收集开销 `n·n!`；两者相加取大是 `O(n·n!)`。而 `n·n!` 恰好也是答案本身的规模，所以这个上界是紧的，无法再优化。”

这段话同时包含**树分析（上界）**和**输出规模（下界）**，比只说其中一个稳得多。

##### 【值得记】三条

1. **总时间 = 边数 × O(1) + Σ节点(该节点的额外工作)**，别用一个平均代价乘总节点数。
2. **节点代价可以是 n 的函数**（复制长度、校验代价），而且**不同层不同**——这才是要按层求和的原因。
3. **树分析给上界，输出规模给下界，两者相等才是 Θ**；只给一边，逻辑上都不完整。

##### 一、节点数怎么数

搜索树里，**每一层表示“已经放了 k 个皇后”**。第 k 层每多放一个皇后，都有多个列可选，但受约束后，候选会逐渐减少：

```
第0层：1 个节点（空棋盘）
第1层：n 个          （第一行任选）
第2层：≤ n(n−1) 个   （去掉同列）
第3层：≤ n(n−1)(n−2) 个
...
第k层：≤ P(n,k) = n!/(n−k)! 个
```

**上界**：总节点数 `≤ Σ P(n,k) ≈ e·n! = O(n!)`。

**【关键，n 皇后和全排列不同】** 全排列里**每条分支都能走到叶子**，走的分支数就是答案数；n 皇后**大量分支被剪掉**，实际节点数远小于 `n!`。

##### 二、每节点代价

按节点类型分，这是上一轮那个框架：

| 节点动作 | 代价 |
|---|---|
| `isValid` 扫同列、左上、右上 | **O(n)** |
| 放 Q / 撤 Q | O(1) |
| 叶子处 `Join` n 行、每行 n 字符 | **O(n²)** |

**你的写法：**

```

收集开销 = 解数 × O(n²)      = Q(n) × n²
```

##### 三、空间三件套

| 部分 | 大小 | 说明 |

| ① 递归栈 | `O(n)` | 深度 n+1 |
| ② 棋盘 `chessboard` | **`O(n²)`** | 主导项 |
| ③ 结果集 `res` | `O(Q(n)·n²)` | 每个解 n 个长 n 字符串 |
| ④ `used` 类数组（优化版） | `O(n)` | col / diag1 / diag2 |

##### 四、两种写法的差异（面试常问）

**① 你的写法（线性扫描 isValid）**

```go
for i := row - 1; i >= 0; i--          // O(n)
for i, j := row-1, col-1; i >= 0 && j >= 0; ...   // O(n)
for i, j := row-1, col+1; i >= 0 && j < n; ...    // O(n)
```

每个节点检查 3 个方向，每个方向最多 n 步 → `O(n)`。**这是 `O(n!·n)` 中第二个因子 n 的来源。**

**② 优化写法（bool 数组，放 Q 时打标、撤 Q 时清标）**

```go
if !colUsed[i] && !diag1[row-i+n] && !diag2[row+i] { ... }   // O(1)
```

**③ 位运算写法（加分项）**

```go
cols, d1, d2 := 0, 0, 0        // 位掩码
available := ^(cols | d1 | d2) & ((1 << n) - 1)
```

常数比 bool 数组更小，是 n 皇后最快的实现方式，面试提到会加分。

|---|---|---|
| 每放一个棋子 | `isValid` 扫同列 + 两条对角线，每条最多 n 步 | **`O(n)`** |
| 每个解收集 | `for i,v := range chessboard { temp[i] = strings.Join(v,"") }`，n 行 × 每行 n 字符 | **`O(n²)`** |

所以：

```
搜索：节点数 O(n!) × 每节点 O(n)   = O(n!·n)
收集：每个解 O(n²)
总：  O(n!·n²)   ← 这就是你的写法的严格复杂度
```

具体差多少：`n=8` 时 `8! = 40320`，`n!·n² = 2,580,480`，**差 64 倍**；`n=10` 差 100 倍。这不是“同阶”或“只差常数”能解释的。

---

##### 那为什么题解都写 `O(n!)`？

**因为刷题圈有一个普遍接受的省略：只保留数量级最大的项，把多项式因子全部省略。**

这个省略严格说并不严谨，原因在于：

- `O(n!)` 和 `O(n!·n²)` **不是同一复杂度类**，前者是后者的子集
- 连 `e` 都被省略了（搜索树节点数是 `e·n!`，不是 `n!`），既然常数级已经省略，再省略一个 `n²` 在刷题语境中也能理解
- LeetCode 官方题解写 `O(N!)`，分析只说明了“第一行 N 种、第二行 N−1 种……”，**默认 `isValid` 是 O(1)**；这个前提并不成立，因此官方这个写法本身也不严谨

**所以结论是**：`O(n!)` 是**宽松的主项表达**，`O(n!·n²)` 是**严格分析**。两种写法都不算错，区别在于是否保留低阶因子，并且要看你答给谁听。

---

##### 按场合选择表述

| 场合 | 建议 | 理由 |
|---|---|---|
| LeetCode 题解、刷题笔记 | `O(n!)` | 行业惯例，没人较真 |
| **面试口述** | **先说 `O(n!)`，再补一句“严格算 `isValid` 是 `O(n!·n)`”** | 既符合预期，又显示你真的算过 |
| 被追问“`isValid` 算不算” | 立刻承认：**算，所以是 `O(n!·n)`**，收集是 `O(n²)` 就是 `O(n!·n²)` | 这是加分时刻，不是扣分时刻 |
| 论文、严格分析 | `O(n!·n²)` | 不容忍省略 |
| LC52（只要个数，不用棋盘的解法） | `O(n!·n)` | 收集开销消失，只剩校验 |

---

##### 一句话

> **你的写法严格是 `O(n!·n²)`；“题解写 `O(n!)`”也没错，只是省略了多项式因子的惯例写法。面试时先答 `O(n!)`，并主动补上“严格是 `O(n!·n)`，因为每步 `isValid` 是 O(n)”，这样既有惯例又显功底。**
